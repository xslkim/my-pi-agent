## 总评

**上一轮的全部意见都已落实，且多数改得比建议更好**：token 系数从「拍一个保守值」升级为「实测值 + 反例对照」；spec 01 的 usage 修复配了真实抓包；`demo/tmp`、`--max-steps`、sha256 基线、SameSite 断言、Node >= 23.6、环境变量必填等 C 类项全部到位。

新增的任务层质量很高：每个任务有独立验收命令、完成动作和「不要做」；预算逐任务拆分且**加总验算无误**（280+250+350+300+200 = 1380）；T02 先于 T03（先有假模型再写解析器）、T20 先于 T21（先锁考卷再进场）、T23 「改动必须指回 run1 记录」、T24 「任务描述逐字一致」这些纪律都是对的。

本轮的新问题集中在两处：**五个会在执行中真炸的坑**（A 类），和一批**任务层与 spec 层的规格漂移**（B 类）——同一个决定在 task 里是一回事、在 spec 里是另一回事，而 tasks README 没有规定「矛盾时以谁为准」。

## A 类：执行时会真出问题

### A1. T20 冒烟链丢了 logout 覆盖

spec 05 的断言表有 10 条，含「登出 200」和「登出后 `/api/me` 401」；T20 的断言链只有 8 条，**logout 完全没测**。后果：agent 可以不实现 `/api/logout` 照样满分交付，而任务 prompt 里明确要求了它。

顺带两处同步：断言 3 丢了 spec 的「错密码且**不下发 cookie**」；T20 把状态码放宽成 2xx/4xx（spec 是精确的 201/409/401）——若有意放宽请在 spec 表注明，否则对齐。

### A2. 裸 `node --test` 会执行 `test/` 下**所有** `.ts` 文件（实测）

在本机 Node v25.2.1 上实测：`test/` 目录内任何 `.ts` 文件——不管叫什么名字——都会被裸 `node --test` 当作测试执行（连一个没有任何 test() 的文件也会作为「文件级测试」跑一遍并 pass；`test/` 之外、不匹配 `*.test.ts` 的文件则不会被发现）。

后果：`test/login-app.smoke.ts` 从 T20 起进入默认测试集且**必然红**（应用还不存在），于是——

- T23 自己的验收门槛「全量测试全绿且断网可跑」**不可能满足**；
- T21/T22 期间任何跑 `node --test` 的检查都会失败；
- T24 写了「把 L5 的真机测试排除在 `node --test` 默认集之外」，但**没有任何任务定义排除机制**。

修法二选一（都已实测验证）：

1. T00 的 `package.json` 脚本改成 `"test": "node --test \"test/*.test.ts\""`——显式 glob 只收 `.test.ts`，冒烟仍按路径单独跑；
2. 把 `login-app.smoke.ts` / `.sha256` / `verify-lock.ts` 移出 `test/`（如根下 `acceptance/`），实测不会被默认发现。

无论选哪个，需同步改 T00、T20、T24 和 plan §5 的树。顺带说明：`test/fake-llm.ts`、`test/verify-lock.ts` 目前也会被当作「文件级测试」无脑跑掉——无害，但既然知道了发现规则，文件放哪应该是刻意决定而非碰巧。

### A3. `.gitignore` 忽略 `.agent/` 与「提交 L5 会话」互相打架

plan §5 要求 `.gitignore` 至少忽略 `.agent/`；T21/T24 又要求**提交** `.agent/sessions/l5-run1.jsonl`、`l5-run2.jsonl`。两者互斥——照做的话要么 `git add` 不上（静默丢产物），要么得靠 `git add -f` 绕过（文档没写）。

修法：在 `.gitignore` 写例外链（`.agent/` → `!.agent/sessions/` → `!.agent/sessions/l5-*.jsonl`），或者干脆把 L5 会话存到 `docs/runs/` 下（本来就是教学产出，和 run1.md 放一起更顺）。

### A4. T00 的类型检查配置自相矛盾，`tsc --noEmit` 必然报错

T00 说 `devDependencies` **只允许** `typescript`，但 tsconfig 里写了 `"types": ["node"]`——没有 `@types/node` 时，`import ... from "node:test"`、`process.env`、`AbortController` 等全部无类型，验收项「`npx tsc --noEmit` 无错」不可能通过。

修法：允许 `typescript` + `@types/node` 两个 devDependencies（仍满足零**运行时**依赖原则），并同步 plan §2 的「`devDependencies` 最多只放 `typescript`」。

### A5. T21 的命令是伪命令，且任务描述「逐字一致」没有机制保证

T21 写的是 `node src/cli.ts ... "$(cat docs/specs/05-delivery.md 的任务描述段)"`——`$(cat ...)` 里是中文占位符，不是可执行命令。tasks README 明说这些文档是**交给 agent 执行的**，照抄必然失败。更深层：T24 要求两轮任务描述「逐字相同」，靠人从 spec 的 markdown 里手动摘抄并不可靠。

修法：把任务 prompt 固化为独立文件 `docs/runs/task-prompt.md`（T20 一并创建并锁定，它本来就是考卷的一部分），T21/T24 都用 `"$(cat docs/runs/task-prompt.md)"`——命令可执行，逐字一致由文件系统保证。

## C 类：小问题

1. **T00 说 `README.md` 和 `.gitignore`「已存在」**——当前仓库根目录没有这两份文件。把它们移进 T00 的「要写的文件」清单。
2. **`-s` 的语义**：T19 说 `-s <name>`，T16 约定存 `.agent/sessions/<name>.jsonl`；spec 05 却写 `-s l5-run1.jsonl`（若实现是「名字加后缀」，会得到 `l5-run1.jsonl.jsonl`）。统一为「name，代码补 `.jsonl`」。
3. **引用的 spec 小节名不存在**：T15 引「上下文管理」（实际是「上下文预算」）、T21 引「run1」、T22 引「补齐工具」、T23 引「加固」（spec 05 的实际小节是「我们要补的能力」「执行流程」）。链接指向文件本身仍可用，但标签误导，建议改成实际小节名。
4. **危险命令确认与「不干预」冲突**：T23 说交互模式（有 TTY）询问 `yes`，但 T21/T24 的 L5 运行都是从终端发起的单发命令——stdin 是 TTY，确认提示会**阻塞等待人在场**，而规则要求全程不干预。应写明：**带 prompt 参数的单发模式视为非交互，直接拒绝，除非 `--yolo`**。
5. **plan §5 的 `docs/runs/` 只列了 run1.md / run2.md**，缺 T24 产出的 `README.md`（对比表）和 A5 建议的 `task-prompt.md`。
6. **T23 步数预警的表述**：「往消息里注入一条提示」没说注入成什么角色（建议 `user` 或 `system`，并注明计入上下文预算），否则实现时又是一个自由发挥点。
