## A 类：技术问题（实现时会踩）

### A1. `done` 事件拿不到 usage（specs/01-talk.md「事件映射」）

`stream_options: { include_usage: true }` 的行为是：usage 出现在**单独的最后一块**里，此时 `choices` 是**空数组**，而 `finish_reason` 在它**之前**的那一块出现。spec 的 `toEvents` 在 `finish_reason` 出现时立即 `yield { type: "done", ..., usage: chunk.usage }`——那一刻 `chunk.usage` 还是 `undefined`；随后真正的 usage 块落入 `if (chunk.usage && !choice)` 这个只有注释的死分支，什么都不记。

后果直通 L4：plan 里 L4 要求「每轮打印耗时与 token」，而这个设计下 usage 永远丢了。

修法（二选一，推荐前者，不用改 `StreamEvent` 类型）：

- `parseSSE` 把 `finishReason` 先存局部变量，**延迟到 `[DONE]` 或流结束时**才 yield `done`，此时 usage 已在手上；
- 或单独加一个 `{ type: "usage" }` 事件。

同时这个场景应该进 L1 测试表：构造「finish_reason 块 → usage 块 → `[DONE]`」的三段脚本，断言 `done` 事件带 usage。

### A2. `chars / 3` 对中文是低估，不是保守（specs/04-usable.md「上下文预算」）

spec 写「中文约 1 token/字、英文约 1 token/4 字符，取 3 是保守折中」——这句话只对英文成立。中文按 chars/3 估算**低估约 2–3 倍**。而这门课全程中文交互：中文 prompt、中文模型输出、中文文件内容。`fitContext` 会以为还剩很多余量，实际早已逼近 65536——**为了避免 400 而写的裁剪，反而保证 L5 还会 400**，恰好死在自己最想防的那条路上。

修法，两行仍零依赖且真正偏保守：

```ts
const cjk = (s.match(/[\u4e00-\u9fff\u3000-\u303f\uff00-\uffef]/g) ?? []).length;
return cjk + Math.ceil((s.length - cjk) / 4);
```

（CJK 字按 1 token 计，对 Qwen 系 tokenizer 略偏高即略保守；其余按 4 字符/token。）

### A3. `truncate` 默认 50KB 对 64K 上下文太大（specs/03-coding.md「约束层」）

50KB UTF-8 中文约 1.7 万字，按 A2 的真实比例折算**一次 `read` 就能吃掉 1/4 到 1/3 的上下文**，还要叠加行号本身占的 token。lesson 04 说「一次 read 可能就是几千 token」，两个数字对不上。建议默认降到 `maxLines = 200, maxBytes = 20_000`，或干脆把截断预算也改成按估算 token 计算，和 A2 用同一个函数，全课一个口径。

### A4. 冒烟测试没指定 spawn 的 cwd，`data.db` 落点不定（specs/05-delivery.md「验收」）

脚本写 `spawn node demo/login-app/server.ts`，测试进程的 cwd 是仓库根目录；任务 prompt 只说「文件 data.db」，server 大概率用相对路径创建——**`data.db` 会落在仓库根，不是 `demo/login-app/`**。断言 10「直接读 data.db 搜明文密码」与收尾「删除 data.db」的路径都成了悬空指代。

修法：spawn 时显式 `cwd: "demo/login-app"`，断言 10 写明读 `demo/login-app/data.db`；或者任务 prompt 要求 agent 用 `import.meta.dirname` 定位数据库文件。前者简单，选前者。

## B 类：文档间不一致

### B1. L1 行数预算 360 > 300，且预算规则不自洽

spec 01 交付物表：60 + 120 + 40 + 60 + 80（fake-llm）= **360**，标题却写 ≤ 300；specs/README 的 L1 行把 `fake-llm.ts` 列进 ≤ 300 的交付里。而 L2 的表只列 src 文件、不含 `loop.test.ts`——**测试文件到底计不计入预算，两课口径相反**。

修法：在 plan §2 定一条明规则，建议「预算只算 `src/`，`test/` 不计」——那 L1 = 280 ≤ 300 成立，1400 总量不变，specs/README 的 L1 交付列加个「（不计预算）」标注即可。不改规则就得把 L1 改成 ≤ 360、总量改 1460，牵一发动全身。

### B2. L5 裸跑命令三处三个样，且 `-c` 语义不对

spec 05 执行流程写 `node src/cli.ts --cwd demo/login-app -c`；lesson 05 第三节写 `-s l5.jsonl`，第五节又什么会话参数都没有。`-c` 是「续聊」，用在**首次空目录裸跑**上语义就是错的（spec 04 自己定义的）。统一成 `-s <file>`，并注明每轮重跑换新会话文件（毕竟「每一轮必须从空目录开始」）。

### B3. plan §5 仓库树缺三个文件

树里没有 `src/prompt.ts`（L3）、`src/repl.ts`、`src/retry.ts`（L4），而 specs/README 的「模块归属速查」三个都有。plan 是总纲，树应补全。顺带：plan §4 的 L1 段落说产出「llm.ts、types.ts、cli.ts」，漏了 `render.ts`（spec 01 有，§5 树里也有）。

### B4. 「并行工具留到 L5 按需」没有下文

plan 和 spec 02 都说串行够用、「并行留到 L5 按需」，但 spec 05 的补能力表里根本没有并行工具这一行。要么把这句改成「留作练习」（lesson 02 练习 4 已有），要么在 spec 05 表里真加一行。现在是空头支票。

### B5. 「给出默认值并在缺失时报可读的错」自相矛盾（specs/01-talk.md「配置」）

代码里 `?? "http://192.168.3.28:8080/v1"` 有默认值，缺失报错的分支永远走不到。二选一：环境变量缺失直接报错、不设默认（对换机器跑的学员更友好，教学上也更清晰，推荐）；或保留默认值、删掉「报错」的说法。

### B6. system prompt 两份差一行（spec 03 vs lesson 03）

spec 03 有 `Explain what you changed after you finish.`，lesson 03 的版本没有。以 spec 为准，lesson 补齐—— lesson 03 自己强调「prompt 说的和代码做的必须一一对应」，两份文档的 prompt 却对不上，有点讽刺。

## C 类：小问题与建议

1. **POSIX 路径演示命令 vs Windows 课**（lesson 03/04）：`mkdir /tmp/demo`、`--cwd /tmp/demo`——L3 花了整整一节讲 Windows 路径的坑，自己的演示命令却用 POSIX 路径。Git Bash 会做 MSYS 路径转换，`/tmp` 传给 node 后落到哪不可靠。换成仓库内相对目录（如 `demo/tmp/`）最省心。
2. **`maxSteps` 提到 30 的传参方式没定义**（spec 05）：CLI 没有对应参数。建议 L5 顺手加 `--max-steps`，一行 argv 解析的事。
3. **校验和基线放哪、谁生成没说**（spec 05「防篡改」）：建议把基线值 commit 进 `test/`（agent cwd 之外），比对脚本也在 test/ 侧，别只写在课堂口头。
4. **冒烟断言可补 `SameSite=Strict`**：任务 prompt 明确要求了，断言 4 却只查 `HttpOnly`，验收强度低于需求。
5. **内网 IP 和 API key 硬编码为代码默认值**（spec 01）+ **引用仓库外绝对路径** `G:\LlmLocal\内网API.md`（plan §3）：私有仓库可接受，但凡有开源/分享打算，这两处先清。plan 里注明「本机路径，仅自用」也行。
6. **缺仓库根 README**：克隆下来只有 `docs/` 和 `pi/`，加一个 5 行的 README 指向 `docs/teaching-agent-plan.md`。
7. **缺 `.gitignore` 计划**：`.agent/sessions/`、`demo/login-app/data.db`、`demo/tmp/` 都该在仓库形状里提一句，不然 L4/L5 打 tag 时会把会话文件和数据库一并提交。
8. **Node 版本措辞**（lesson 01「环境」）：`>= 23` 不够准——类型剥离默认开启是 23.6 起，23.0–23.5 要加 flag。写成 `>= 23.6` 或直接 `>= 24` 更稳。
