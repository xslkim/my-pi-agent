>>> 开场：毕业考 #B01
欢迎来到第五课，让 agent 交付。
这是全系列的毕业考，也是最后一课。
前四课写出的 agent，今天原样上考场。
不为这场考试，加任何新功能。
只修考场上真实暴露出来的 bug。
我们从 **l4-usable** 这个 tag 接着走。
考题：从空目录，交付一个能用的登录应用。


>>> 考卷设计 #B02
先看这份考卷，是怎么设计出来的。
冒烟测试和任务描述，两份文件，预先写好。
冒烟测试一共十项，从注册一直查到登出。
然后，用校验和，把这两份文件锁死。
校验和写进 lock.sha256。
verify-lock.ts 负责校验，考卷一动就会发现。
agent 只许答题，**不许修改**考卷。
这就叫验收先行：标准定死，再让 agent 上场。


>>> 考题：最小登录应用 #B03
考题本身，是一个最小登录应用。
server.ts 用零依赖的 node:http。
四个路由：register、login、me、logout。
node:sqlite 存用户。
scrypt 加盐哈希，**不存明文密码**。
token 用 randomUUID 生成。
放进 httpOnly cookie 里。
全部产物落在 demo/login-app 目录。


>>> run1 裸跑 #B04
第一遍考试，记作 run1，原样裸跑。
不为考试写任何新功能。
agent 读任务描述，规划，然后动手写代码。
写完应用，它自己起服务做自测。
整个过程，压缩成这段延时录屏。
从空目录，到一个能跑的登录应用。
考卷一评，冒烟测试**十项全过**。
第一次上场，就交出了一份答卷。


>>> 但是：挂死与救援 #B05
但是，这份答卷背后，并不干净。
agent 用 bash 起后台服务做自测。
后台进程**永久挂死**，再也不返回。
整个会话卡在那里，考试进行不下去。
人工救援一次，才把考试救回来。
这一遍的消耗：**十一步、十七次工具调用**。
会话 token 约十一点六 K。
问题出在哪里？下一屏拆开看。


>>> 失败分析：回炉前四课 #B06
失败不是新坑，回炉前四课的代码里找。
挂死发生在第三课写的 bash 工具。
后台任务这个场景，在第三课露出了死角。
修复记作 T23，专门加固后台任务。
改动全部落在 bash.ts。
新增四十六行，删除六行。
净增四十行，全系列来到**一千一百零六行**。
这是本集唯一一次改动代码。


>>> run2 加固后再考 #B07
加固之后，原样再考一遍，记作 run2。
同一份考卷，同一份十项冒烟测试。
agent 没变，只换了加固后的 bash。
这次 bash 自测只用了**六百五十三毫秒**。
正常返回，从头到尾不用人救。
冒烟测试的结果，还是十项全过。
七步、九次工具调用，会话 token 约六点八 K。
同一遍考卷，两遍结果，值得对比。


>>> run1 vs run2 对比 #B08
把两遍考试的成绩单，放在一起看。
步数从十一步降到七步。
工具调用从十七次降到九次。
会话 token 从十一点六 K 降到六点八 K。
人工救援，从一次降到**零次**。
任务两次都做成：差别不在能不能。
差别在，**要不要人救**。
加固的价值，就写在这张对比表里。
