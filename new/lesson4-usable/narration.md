>>> #B02
先看第一项：**REPL**，读一行、答一轮的循环。
现在跑一次命令，只能问一句话。
我们把它改成对话。
**readline** 读进一行输入，就跑上一轮。
打印回答，再回到提示符，等下一句。
问完一句，不用再重新开场。
上下文顺着对话，一路滚下去。
整块逻辑收进 repl.ts，一百一十行。
单发的 CLI，就这样变成了 REPL。


>>> #B03
第二项是中止。模型跑偏了，总不能干等。
按下 **Ctrl+C**，只停当前这一轮。
关键是一个取消信号：**AbortSignal**。
它要一路贯穿：fetch 和工具，一环都不漏。
先贯穿到 fetch，正在等的请求立刻松手。
再贯穿到工具，跑着的命令也能停下来。
只要有一环没贯穿，agent 就会僵住。
停掉的是这一轮，会话还在原地。


>>> #B04
第三项，把对话持久化。
每一轮对话，都追加写进一个文件。
格式叫 **JSONL**：一行就是一条 JSON 记录。
关掉终端，记录也不会丢。
退出之后想接着聊，就加上 -c 参数。
上一轮的上下文，原样回到对话里。
看录屏：退出，再续聊，它还记得。


>>> #B05
模型能记住的对话，是有上限的。
第四项改造，就叫上下文预算。
每轮请求前，先估算文本量，单位叫 **token**。
一旦超过阈值，就裁掉最老的轮次。
为什么裁最老的？越近的对话，越值钱。
最近的对话原样保留，请求照常发出。
不裁掉会怎样？上限是**六十四 K**，聊超了服务端直接报四百。


>>> #B06
第五项，重试。
撞上 **429** 或者超时，多半是暂时性错误。
处理办法是退避：等一等，再试一次。
每次等待的间隔，越来越长。
硬刚只会再撞一次，退避才过得去。
请求照旧写，重试包在最外面。
这套逻辑收进 retry.ts，一共三十九行。


>>> #B07
顺手再加一件小事：可观测，让每轮都看得见。
每一轮结束，打印**耗时与 token**。
这一轮跑了多久、烧了多少，一眼可见。
哪一轮慢、哪一轮贵，清清楚楚。
成本看得见，优化才有下手的地方。
数字不骗人，调优先从这里看。


>>> #B08
先交代口径：预算只算 src 目录。
src 累计**一千零六十六行**，比上一课多了三百三十一行。

总量余量还充足，所以没有回砍代码。
三百行不是红线，是提醒。
