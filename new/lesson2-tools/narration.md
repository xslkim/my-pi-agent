>>> 钩子：模型算不对 #B02
先做个实验：直接问模型，二十一乘二等于多少。
它很可能脱口而出一个错答案，还特别自信。
你再追问，它还能把错的圆得头头是道。
问题不在努不努力，在于它只有语言，没有手脚。
它需要的不是更努力，而是 **工具**。


>>> 协议：tool_calls 增量 #B03
模型想调工具时，finish_reason 不再是 stop，而是 **tool_calls**。
工具名和参数，通过 delta 一块一块流式给出。
arguments 是字符串碎片，要 **按 index 累加**，拼完整再 JSON.parse。
少拼任何一片，JSON.parse 都会当场炸掉。
这是上一集的 SSE 解析之上，第二类增量。


>>> Tool 接口四件 #B04
一个工具，由四件东西组成。
**name** 和 description，告诉模型什么时候用它。
parameters 是手写的 JSON Schema，描述入参的形状。
execute 是真正干活的函数，接收参数，返回结果。
我们的 calculator，只有 **二十四行**。


>>> 坑一：类型只是注释 #B05
第一个坑：JSON Schema 里的类型，对模型只是建议。
模型很客气，但它不保证守类型约定。
它可能把二十一，当成字符串 "21" 传进来。
所以 execute 里必须做 **运行时校验**，不能信类型声明。
类型只是注释，校验才是防线。


>>> agent loop #B06
工具跑完，结果怎么回去？这就是 **agent loop**。
发起请求，模型返回 tool_calls。
我们执行对应的工具，拿到结果。
把结果作为 role 是 tool 的消息，追加进对话历史。
然后再发起请求，每一轮对话历史都在变长。
直到模型不再调工具，直接给出回答。


>>> 坑二：没有刹车的循环 #B07
第二个坑：循环不能没有刹车。
模型可能一轮接一轮地调工具，把上下文烧光。
没有上限的循环，就是把控制权交给了运气。
所以 loop 必须设一个 **maxSteps** 上限。
步数到顶就强制停下，把控制权交还给人。


>>> 演示：calculator 算对 21*2 #B08
跑起来看看：我们问它，二十一乘二等于多少。
模型返回 tool_calls，调用 calculator。
注意看，它先调工具，再回答。
工具算出结果：二十一乘二等于 **四十二**。
结果回喂之后，模型再组织语言，给出答案和解释。
这一次，答案是算出来的，不是背出来的。


>>> 回归：假模型守住防线 #B09
这些坑，怎么保证不再犯？
回归测试里放一个假模型，故意返回字符串入参。
再让它去调一个不存在的工具。
两种异常，都必须被稳稳接住。
每次改动后跑一遍，防线就一直在。
全系列 **一百一十个测试通过，一个跳过**。
