这一集从 **l2-tools** 出发，让它真正能改代码。
四个**受约束**的工具：read、write、edit、bash。
外加一道统一的安全收口，guard.ts。
学完这一集，它就能读懂并修改你的项目文件。


>>> #B02
先上全景，本集看六个文件。
四个工具：read、write、edit、bash。
守门员 guard.ts，把路径检查统一收口。
再加 prompt.ts，用系统提示词约束模型。
src 累计从四百二十二行涨到 **七百三十五行**。


>>> #B03
第一个工具 read.ts，四十七行。
读文件必须带 **offset / limit**，大文件分段读。
返回结果之前，还要再做一次输出截断。
不截断的话，一个五 MB 的文件，
就能炸掉 **六十四 K** 的上下文。


>>> #B04
编辑工具 edit.ts，六十行。
它把 old_string 替换成 new_string。
为什么不用行号？行号会漂移。
核心约束：**old_string 在文件里必须唯一**。
匹配到两处就直接报错，一个字符都不改。


>>> #B05
把这两个约束拆掉，看看会发生什么。
edit 不查唯一性，匹配两处，就改错地方。
read 不做截断，一次读进整个大文件。
五 MB 灌进六十四 K，上下文瞬间爆掉。
所以这些约束不是优化，是**安全底线**。


>>> #B06
最危险的工具是 bash.ts，八十九行。
它自带三道保险：超时、cwd 约束、输出截断。
命令跑超时就杀掉，不许永远挂着。
杀的时候连整个进程组一起杀，不留孤儿。
工作目录被约束，输出超长照样截断。


>>> #B07
Windows 上有个隐蔽的坑。
System32 目录下的 bash，其实是 WSL。
它眼里没有盘符，G 盘是 /mnt/g。
路径对不上，命令全部打偏。
所以优先用 Git 自带的 bash，否则回退 PowerShell。


>>> #B08
所有路径检查，统一收口在 guard.ts，六十四行。
每个工具动文件之前，先过它这一关。
解析后的绝对路径，必须还在工作目录里。
想跳出工作目录？直接拒绝。
连指向外部的软链接，也一起挡住。


>>> #B09
最后一道约束不在代码里，在 prompt.ts。
系统提示词只有**十二行**。
它告诉模型：先读后改，优先用 edit。
工具的规矩，在提示词里再讲一遍。
prompt 里说的每一条，代码里都必须真的强制。


>>> #B10
看实际效果：让 agent 改一个 hello.js。
它先调 read，读文件、看现状。
再调 edit，用 old_string 定位。
唯一匹配，精确替换。
工具调用走完，hello.js 就改好了。
这就是受约束工具干活的样子。


>>> #B11
和 pi 对照一下。
我们的 edit 六十行，pi 是 **一百二十七加五百行**。
多的部分做多重编辑、行尾和 BOM 处理、unified diff。
我们的 bash 八十九行，pi 的执行环境 **六百九十五行**。
多的部分是 Result 错误模型、进程树 kill、跨平台 shell 探测。
