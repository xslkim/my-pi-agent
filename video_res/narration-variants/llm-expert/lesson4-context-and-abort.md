>>> 上下文是稀缺资源 #B01
六万四的窗口，真实任务里很快见底
大头不是对话，是 **工具结果**
一次 read 几千 token，几轮就贴顶
超限不是警告，是 400，会话作废
所以预算要自己划：两万四，约窗口四成
真超六万五，服务端才替你报错


>>> token 估算必须实测 #B02
零依赖，不引 tokenizer，用估算
但系数必须实测
方法很土：max_tokens 设一发请求，读 usage 字段
本机实测：中文零点五八 token 每字
代码三点七字符每 token
一刀切断以三，中文低估近两倍
低估的裁剪器等于没有裁剪器


>>> 成组裁剪 #B03
裁剪策略：保 system，保最近四轮，从最老的丢
关键约束：按轮 **成组** 丢
assistant 的 tool_calls 和它的 tool 结果同进同出
丢一半就产生孤儿 tool_call_id
你为了避免 400 做的裁剪
制造了另一个 400


>>> 与生产的差距 · compaction #B04
生产实现不直接丢历史，做 **compaction**
用一次模型调用把旧对话压成摘要
保住要点，代价是多一次调用和摘要失真
丢弃与压缩，没有免费的午餐
这一课选丢弃，但要知道另一个选项的价码


>>> 中止是三层协议 #B05
中止不是杀进程，是信号传播
**AbortSignal** 必须贯穿三层
传给 fetch，否则 SSE 继续流
传给工具，否则 bash 子进程继续跑
loop 自己检查，否则下一步照常发起
缺任何一层，Ctrl+C 就是坏的


>>> 中止的残局 #B06
中止后对话状态不能留洞
已产出的部分输出要入历史
没跑完的工具，补一条 aborted 结果
否则下一轮违反消息不变量，又是 400
状态完整性优先于表面干净


>>> 会话落盘 #B07
会话持久化用 **JSONL**：一行一条，追加写
崩溃、断电、Ctrl+C，最多丢最后一行
读入时跳过坏行，半行不毁掉整个会话
代价：没有分支、没有索引、没有压缩
生产的会话层是一棵对话树加状态机
这里是一份日志，差距是显式选择


>>> 重试纪律 #B08
重试要按错误语义分类
网络错误、5xx、429：指数退避加抖动
429 尊重 Retry-After
其余 4xx **绝不重试**：请求本身就是错的
重试只是把同一个错误再发三遍
还会掩盖真正的 bug
每次重试都打印，不静默


>>> 重试窗口 #B09
流式请求只有一段可重试窗口
从发起到拿到 **第一个 token**
实现里收得更紧：响应头一到手就不再重试
这个窗口内失败，可以安全重来
已经吐出半个 completion 再重放，内容必然重复
首 token 之后的失败，只能作为错误上报
