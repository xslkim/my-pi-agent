>>> 交付而不是演示 #B01
最后一集不讲课，做 **交付**
空目录里做一个登录应用
四个接口，sqlite 存用户
密码 scrypt 加盐哈希，禁止明文
会话用 httpOnly cookie，前端原生 JS
两轮运行，prompt 逐字一致，全程不干预


>>> 验收先行 #B02
考卷先于 agent 存在
十条冒烟断言，在 agent 进场前写好并锁定
从注册到登出，覆盖全部接口
最后一条最狠
直接搜数据库文件的原始字节
明文密码一个字节都不许出现
没有自动化验收的 agent 任务，等于没有需求


>>> 两道锁 #B03
agent 不许改考卷，上两道锁
第一道，路径约束让文件工具够不到验收目录
但 bash 能用绝对路径绕过，这是已知缺口
所以第二道：**sha256 校验和**兜底
考卷改动一个字节，本轮验收作废
声明式约束挡不住能执行任意命令的工具
这正是生产实现要做沙箱和权限确认的原因


>>> run1 实况 #B04
第一轮裸跑，真实事故，不是剧本
它写完五个文件，做得很顺
然后后台起服务自测
接着，bash 工具 **永久挂死**
人工杀掉三千一百端口的进程才恢复
十一步、十七次工具调用
应用做出来了，验收也过了
但过程需要人救一次


>>> 死锁解剖 #B05
根因在进程等待语义
工具等的是 **close**：全部 stdio 关闭
而不是 exit：进程退出
bash 被超时杀掉了
但后台服务进程还活着，手里握着管道
close 事件永远不来
一个接口层的语义选错，表现为死锁


>>> 三层修复 #B06
修复挖出来三层
第一层：以 exit 为准返回，宽限一秒后主动 destroy 流
第二层：Git Bash 的后台任务不在 Windows 进程树里
外部杀不到，只能换思路
第三层：让 bash 退出前自己 kill 掉全部后台任务
一和三是通用的，二是 Windows 专属
每一步都有实验证据


>>> 证据驱动的加固 #B07
预判清单里列了七项缺口
run1 没发生的，一项都不做
只修真实出现的死锁
加固由 **证据** 驱动，不由想象驱动
失败记录表，是这一课最重要的产出


>>> run2 #B08
同一个命令，同一个 prompt，从空目录重跑
同样的后台自测场景真实复现，这次没挂死
**七步**、九次工具调用
上次是十一步、十七次
考卷校验和一致
十条冒烟断言，全绿
人工救援次数：零


>>> run1 vs run2 #B09
两次都交付了同一个登录应用
差别不在产出
run1 需要人工救一次，run2 一次都不需要
把人从救援里解放出来
这才是加固的意义
