>>> 四个工具 #B01
coding agent 的工具集收敛到四个
read、write、edit、bash
裸实现各一行 fs 调用，二十分钟写完
难点不在读写，在约束
无约束的 bash
等于把任意命令执行权交给一个采样器


>>> 路径约束 #B02
第一个约束：路径不得逃逸工作目录
resolve 之后用 **path.relative** 判越界
字符串前缀判断是错的
work 和 work-evil 共享前缀
路径包含是路径语义，不是字符串语义
越界就抛错，并保留模型的原始输入


>>> 软链与 TOCTOU #B03
relative 挡得住两点，挡不住符号链接
已存在的路径要用 realpath 再验一次真实位置
但检查与使用之间仍有竞态窗口
这就是 **TOCTOU**
堵死它需要 openat 这类系统调用，Node 没有暴露
工具层挡的是模型的误操作，不是主动攻击者
后者是沙箱的职责，这条边界要诚实画出来


>>> 截断与 token 预算 #B04
一个五 MB 的文件进上下文，服务端直接 400
整个会话作废
read 必须截断：默认两百行、二十 KB
按实测系数折算，约占六万四窗口的百分之八
截断后必须显式告知模型
静默截断比报错更糟：它会基于残缺信息继续推理


>>> edit 的唯一匹配 #B05
edit 用字符串替换，最大的风险是静默改错
规则只有一条：old_string 必须唯一
出现多次就拒绝执行，报错列出全部行号
并提示补充更多上下文
这句提示的读者还是模型
它会读到行号、扩大上下文、自己重试
错误信息是 agent 控制面的一部分


>>> 超时与进程树 #B06
bash 会挂死：一个等输入的命令永远不还
修法是超时，加 **杀进程树**
注意是树，不是进程
只杀 bash，子进程变成孤儿占着端口
POSIX 杀进程组
Windows 用 taskkill 斜杠 T


>>> shell 必须显式 #B07
Windows 上系统里有三个 bash
System32 那两个是 WSL
WSL 眼里 G 盘是斜杠 mnt 斜杠 g
写错地方，报错还看不出根因
排查这个能耗掉一下午
所以 shell 显式探测，优先 Git Bash
启动时打印一次实际路径自证
执行环境不能靠 PATH 碰运气


>>> prompt 与代码对偶 #B08
system prompt 与代码强制必须一一对应
只在 prompt 里写不要越界，代码不检查，等于没写
反过来，代码强制了但 prompt 没说
模型会反复撞墙，浪费轮次
prompt 是建议层，代码才是约束层


>>> 与生产实现的差距 #B09
pi 的 edit 连 diff 生成六百多行
执行环境近七百行
多重编辑、行尾保持、BOM、冲突检测
它踩了四十个坑，这一集演示四个
四个足够看清这类工具的设计原则
