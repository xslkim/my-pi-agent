# NOTES — llm-expert 变体的改写策略

- **面向谁**：已经熟悉 LLM 底层（token 化、采样、上下文窗口、function calling、流式推理服务）的工程师。因此删除原版里全部概念科普、情绪铺垫和课堂组织话术（"你会有点兴奋""答案短得让人失望"），每块第一句直接进入协议字段或机制本身。

- **结构重设计**：原版按"五层能力递进"（说话→动手→改代码→好用→交付）组织；本版改为按**接口层问题域**组织五集：SSE/流式解析 → tool calling 协议 → 宿主侧工具约束 → 上下文与中止 → 交付与评估。每集聚焦一个"模型之外、系统之内"的工程面，块数由原版 11–19 块压缩为 9–10 块，单块信息密度提高。

- **术语与高亮**：直接用协议字段名说话——`delta.content`、`finish_reason`、`tool_calls`、`stream: true`、close vs exit、TOCTOU、wire format、compaction——不打比方、不绕弯。`**` 高亮只给真正影响实现的术语（不变量、兼容性税、成组、证据等），不给"黑盒""兴奋"这类叙事词。

- **教学实现 vs 生产实现**：每集保留一块明确的差距对照（pi 的 1577 行兼容层、796 行 loop、compaction、沙箱、对话树状态机），从原版的"兼容性税"叙事改为冷静的清单式差距陈述，并说明哪些差距是显式选择、哪些是真坑。

- **事实核对**：所有数字与机制均回读仓库核对——`src/llm.ts` 149 行、pi 兼容层 1577 行 / loop 796 行（docs/lessons/01、02）、上下文预算 24K / 窗口 65536、实测系数中文 0.58 token/字与代码 3.7 字符/token（`src/context.ts`、docs/lessons/04）、重试窗口收紧到响应头（`src/llm.ts:52-53`）、run1 死锁的 close/exit 语义与 MSYS 进程树问题、run1 11 步 17 次调用 vs run2 7 步 9 次（docs/runs/run1.md、run2.md）。未沿用原版旁白中与源码注释有出入的表述（如重试窗口原版说"第一个 token"，源码实际是"响应头到手"，本版两者都写并注明实现收得更紧）。

- **行设计**：每块 4–8 行、行均 ≤ 30 字（上限 50），短句、无寒暄，TTS 节奏冷而密；块间两个空行分隔，无任何 @ 指令。
