>>> 这门课讲什么 #B01
这门课不解释模型内部，只处理一个工程问题
模型与宿主程序之间的接口层
token 流怎么进内存，tool call 怎么回传服务端
上下文窗口怎么管理，失败怎么重试
五集，从零手写一个 coding agent，总计约一千一百行
终点不是复刻 Claude Code，是读懂它的每一行


>>> SSE 协议 #B02
先看线上协议：**SSE**
本质是一个不主动结束的 HTTP 响应体
每个事件以 data 冒号开头
事件之间用两个换行分隔
终止符是 data 中括号 DONE
服务端也可能不发 DONE 直接断流
写代码之前，先 curl 加 -N 看真实字节


>>> 事件负载 #B03
每个事件的负载是一帧 JSON
**delta.content** 是正文增量，不是累计文本
delta.reasoning_content 是思考增量，llama.cpp 的方言
**finish_reason** 是 stop reason：stop 或 tool_calls
所谓流式，是服务端把一次 completion 拆成增量帧
客户端的职责是重组，不是生成


>>> 天真解析器 #B04
直觉写法：每收到一个 chunk 就切一次
这隐含两个假设，两个都是错的
假设一：TCP 按事件边界交付，它不保证
假设二：字节按字符边界切开，UTF-8 不保证
一个汉字三个字节，正好可以断在中间
半截 JSON 直接 parse 报错，半截字节变成乱码


>>> 缓冲与流式解码 #B05
修法一：**跨 chunk 缓冲**
拼进 buffer，循环找双换行，找到完整事件才切
切一半的留在缓冲区，等下一块到齐
修法二：decode 时传 **stream: true**
让 TextDecoder 自己持有残缺的尾部字节
两行修复，但必须先看见坏掉才会记住


>>> 延迟的 done #B06
第三个坑只有抓真机字节才能看到
finish_reason 和 usage **不在同一帧**
带 usage 的末帧，choices 是空数组
看到 finish_reason 就收尾，usage 永远拿不到
正确做法：两个字段各自缓存
收到 DONE 或流结束时，统一发 done 事件


>>> 假模型服务器 #B07
这些边界靠真机偶发去撞，不可复现
所以写一个 **fake LLM server**，按脚本回放字节流
可以把事件切在任意字节偏移，包括汉字中间
全部测试毫秒级、离线、确定性
能伪造协议，才算真正理解协议


>>> async generator 形态 #B08
客户端暴露为 **async generator**
调用方 for await 消费，break 即取消
背压由迭代协议天然处理，不用自己实现
这个形态决定了第四集中止功能的成本
测试也简单：收集成数组就能断言


>>> 与生产实现的差距 #B09
对照 pi 的兼容层：一千五百七十七行
我们只服务一个 llama.cpp 端点，一百四十九行
差距是四十家厂商的协议方言
光思考字段它就要认三个名字，还得去重
单端点不必交这笔 **兼容性税**
但要知道税单长什么样
