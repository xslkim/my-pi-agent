>>> 那个工具卡片是什么 #B01
用 Claude Code 时你肯定见过那个卡片
Bash、Read、Edit，带一串参数，跑完打个勾
第二课就拆它：聊天机器人和 agent 的区别
答案短得让人失望，**一个 while 循环**
模型自己什么都不会执行
让它成为 agent 的，是我们写的这段循环


>>> 给模型一本说明书 #B02
第一步，请求体里加一个 **tools** 字段
每个工具就是名字、描述、一份手写 Schema
模型看到的只有这张说明书，没有代码
注意描述里那句：不要自己心算，请用计算器
你见过模型绕过工具直接口算吧
没有这句话，它就经常这么干


>>> 模型没有执行任何东西 #B03
带上 tools 再问，响应就变了
正文是空的，多出来 **tool_calls**
finish_reason 也变成了 tool_calls
看清这一点：模型没有执行任何计算
它只是按格式说了一句
**请帮我调这个工具，参数如下**
执行，永远是我们的代码干的


>>> 坑一 · 参数是碎片 #B04
第一个坑，工具参数是**碎片**
真实抓包里，数字 21 分成 2 和 1 两片吐出来
只有第一片带 id 和名字，后面只有 index
必须按 index 累加，流结束后再 parse
中途 parse 一定失败
而且失败的样子，看起来像个合法的中间状态


>>> 坑二 · 类型不是校验 #B05
第二个坑，类型不是校验
TypeScript 的类型在运行时根本不存在
而模型一定会传错
字符串当数字、缺字段、调不存在的工具
所以要手写一个六十行的校验器
数字宽容转换，错误信息精确到字段名


>>> 你见过的自我纠正 #B06
你肯定见过这个画面
agent 调错了工具，愣一下，然后自己改对了
关键设计：校验失败**不抛异常**
把错误文本当工具结果，回给模型
模型读到 field op is required，会自己补上重试
这是 agent 最重要的**自愈机制**
也是它看起来有智能的主要来源之一


>>> 就这，一个 while #B07
现在写心脏，**agent loop**
调模型，收到 tool_calls 就执行
结果作为 tool 消息塞回去，再调模型
直到模型不再要工具，循环结束
去掉所有包装，所谓 agent 就是这个 while
你每天付费用的那个东西，核心就是它


>>> 消息顺序铁律 #B08
loop 里有一条铁律
带 tool_calls 的 assistant 消息
必须紧跟它的全部 tool 结果
少一条，下一次请求直接 **400**
报错信息完全看不出根因
你遇过 agent 聊着聊着莫名 400 吧
这是最常见的一类根因，第四课它还会回来


>>> 你见过的死循环 #B09
你刷到过 agent 反复调同一个工具吧
额度在烧，它停不下来
真实模型确实会陷进去，尤其工具一直报错时
所以 **maxSteps 是必需品**，不是防御性洁癖
没有上限，六万四的上下文会被烧光
然后服务端 400，整个会话作废
本地免费模型上，这一幕很便宜
在按 token 计费的云上，这一幕**很贵**


>>> 真机才踩得出的坑 #B10
分享一个只有真机踩得出的坑
回传 tool_calls 必须用**线上格式**
带 type 冒号 function，再包一层 function
直接发内部形状，llama.cpp 直接 500
假模型测不出这个问题
因为它验的是我们自己定义的形状
这也是为什么测试永远不能替代真机


>>> 见真章 #B11
问它，用计算器算 21 乘 2 加 8
它先调乘法拿到 42
再把 42 喂给加法，得到 50
注意，第二次调用的参数来自第一次的结果
你见过的链式工具调用，就是这么串起来的
到这里，它是一个 **agent** 了
