>>> 为什么真任务会崩 #B01
demo 里漂亮的 agent，一到真任务就崩
你用 Claude Code 跑长任务，也崩过吧
真任务意味着四件事
聊得久、跑得长、会出错、要续上
这四件事**没有一件和智能有关**
但少任何一件，它都会死在半路


>>> 斜杠命令 #B02
先把一次一问，变成坐下来一直聊
斜杠命令本地处理，**绝不发给模型**
查上下文用量、清空历史、另存会话
你在 Claude Code 里敲的斜杠命令，同理
但注意，我们刻意不做 **TUI**
学员要始终看得见发生了什么


>>> 为什么有时停不下来 #B03
你按 Ctrl+C，有时停得干脆，有时不停
这一课的难点就是**中止**
**AbortSignal**，就是 fetch 那个取消信号
它必须贯穿三层，缺一层就漏
不传给 fetch，SSE 继续流，字还在蹦
不传给工具，bash 子进程继续跑
loop 不检查，当前停了，下一步照常开始
三层都接上，Ctrl+C 才真正停得下来
REPL 用 generating 标志区分两种时刻
干活时停本轮，空闲时才退出


>>> 中止的残局 #B04
中止之后，还有一盘残局
已经产生的部分输出，必须存进历史
没执行完的工具，补一条 aborted 结果
为什么这么较真
丢了它，下一轮上下文就有空洞
还记得第二课的 400 铁律吗，就是它
**完整性比干净更重要**


>>> 续聊的原理 #B05
claude 杠 c 能续聊，原理这节自己写
会话用 JSONL，一行一条消息，追加写
为什么不是退出时写整个文件
因为 Ctrl+C 和断电都不该丢历史
追加写最多丢最后一行
读取时跳过坏行
崩溃留下的半行，不至于毁掉整个会话


>>> 上下文谁吃掉的 #B06
聊久了它报上下文不足，到底是谁吃掉的
history 只报总量，分类统计要自己加
结论先给你：**工具结果是大头**
一次 read 就是几千 token，几次就见底
两万四是我们自划的安全线，约为窗口四成
超它就地裁剪；真超六万五，服务端才 400


>>> 系数要实测 #B07
token 估算不引依赖，但系数要**实测**
方法很土：发一次请求，读 usage 字段
中文零点五八 token 每字
代码三点七字符每 token
一刀切断以三，中文低估近两倍
按一字一 token，又白白丢掉历史
十分钟的实测，胜过博客抄来的经验值


>>> Compacting 的最小版 #B08
Claude Code 聊久了会压缩对话，你见过
我们的裁剪是它的最小版，朴素但必须正确
system 永远保留，**最近四轮**优先保
从最老的开始丢
关键是**成组**：assistant 和它的 tool 结果同生共死
只丢一半，就产生孤儿 tool_call_id
你为了避免 400 做的裁剪
制造了**另一个 400**


>>> 你见过的限流重试 #B09
网络会抖，重试要克制
网络错误、五开头、四二九，指数退避加抖动
其余四开头的，**绝不重试**
四百通常是消息结构有错
重试只是把同一个错再发三遍
还会掩盖真正的 bug
每次重试都打印一行，不要静默
「有点慢」的背后，可能藏着五次失败


>>> 首 token 分界线 #B10
流式请求的重试窗口只有一段
从发起到收到**第一个 token**
实现里收得更紧，**响应头**一到手就不再重试
窗口里失败，可以安全重来
已经吐了一半再重放，内容会重复
所以首 token 之后的失败
只能作为错误上报


>>> 见真章与 pi 对照 #B11
连续聊十几轮，不炸上下文
中途 Ctrl+C，只停本轮，还能继续
退出后再续聊，它记得上文
现在它是一个你愿意每天打开的工具了
对照 pi：它会把旧对话压缩成摘要
丢历史还是压历史，没有免费的午餐
一千二百行，下一课，让它交付真东西
