>>> 故障 A · 路径逃逸 #B03
故障一，让它读工作目录外面的文件
它读到了，工作目录形同虚设
修法是 resolveInside
用 path.relative 判断是否越界
抛错，并保留模型的原始输入


>>> 前缀陷阱 #B04
顺带一道陷阱题
为什么不用字符串前缀判断
因为 work 和 work-evil，前缀一模一样
**字符串前缀不等于路径包含**
必须先 resolve，再 relative
再看结果是不是以两点开头


>>> 为什么有权限确认 #B05
相对路径挡住了，软链还挡不住
一个指向外部的链接，就能绕过全部检查
修法：已存在的路径用 realpath 再验一次
但从检查到真正读写，仍有一个竞态窗口
堵死它需要的系统调用，Node 没有暴露
**诚实画出约束的边界**，比假装安全有价值
现在你明白 Claude Code 的权限弹窗了
工具层挡不住的，只能交给人和沙箱


>>> 故障 B · 上下文爆炸 #B06
故障二，让它读一个几 MB 的大文件
请求直接 400，整个会话作废
这是 agent 最容易的死法之一
修法是截断，默认两百行、二十 KB
按实测比例算，约占上下文的百分之八
关键：截断后**必须告诉模型**
静默截断比报错更糟
模型不知道被截了，会拿半份内容接着干


>>> 故障 C · edit 改错地方 #B07
你肯定收过这条报错：匹配到的内容不唯一
故障三就是它：文件里有三处相同代码
replace 只改第一个，而且**静默失败**
修法是这一课最重要的规则：唯一匹配
出现多次就拒绝执行，并列出全部行号


>>> 错误信息写给谁 #B08
注意报错里的两个细节
行号，和那句「补充更多上下文」
它们都不是写给人的，是**写给模型的**
模型读到，会去读那几行，补上下文重试
你在界面上看到它愣一下又改对了
一半功劳在这种报错文本里
好的错误信息，是 agent 的一部分


>>> 故障 D · 命令挂起 #B09
故障四，命令挂起
一个等待输入的命令，能让 agent 永远卡死
你按 ESC 的时候，背后就在处理这个
修法是超时，加**杀进程树**
注意是进程树，不是进程
只杀 bash，会留下孤儿进程占着端口
Windows 用 taskkill 斜杠 T，POSIX 杀进程组


>>> Windows 的三个 bash #B10
Windows 上还有一个专属大坑
系统里有三个 bash，前两个都是 **WSL**
在它眼里 G 盘是斜杠 mnt 斜杠 g
agent 用错它，文件写到另一个世界
报错还完全看不出根因，能排查一下午
所以 shell 显式探测，优先 Git Bash
启动时打印一次路径，自证清白


>>> system prompt 五条 #B11
工具装好了，还得告诉模型怎么用
system prompt 只有五条，短、具体、可执行
你可以把它理解成最小的 **CLAUDE.md**
核心原则一句话
**prompt 说的和代码做的必须一一对应**
只写不做等于没写
做了不说，模型会反复撞墙浪费轮次
