>>> 你每天用的东西，今天拆开 #B01
你用 Claude Code 或 Cursor，不是一天两天了
它读文件、改代码、跑命令，偶尔翻车
这些外在行为你熟得很
但你没看过它的内部
这个系列就干一件事：**拆机**
把你每天用的东西拆开，装回去，再拆给你看


>>> 拆机路线图 #B02
五节课，从里往外拆五层
**说话**：回答为什么一个字一个字蹦出来

**好用**：中止、续聊、上下文，你每天用的那部分

>>> 第一课拆什么 #B03
第一站，拆最底层：一次模型调用
你在聊天框里每按一次回车，背后就发生一次
大多数人只见过 SDK 的一个函数
这一课扔掉 SDK，从字节层面重造它
学完你会知道，流式输出的每个怪癖是哪来的


>>> 先看真实字节流 #B04
不写代码，先 curl，看线上真实的字节
屏幕上滚过的东西叫 **SSE**
每个事件以 data 冒号开头
事件之间用两个换行分隔
最后以 data 中括号 DONE 收场


>>> 解剖一个事件 #B05
拆开一个事件，里面三块东西
content 是正文**增量**，不是完整回答
reasoning_content 是思考过程
finish_reason 是模型停下的原因
所谓流式，就是把回答拆成碎片逐个发给你


>>> 你见过的丢字 #B06
如果你见过回答卡住、丢字、或者半截乱码
根子通常就在这一层
最直觉的解析器，收到一块就切一块
但 TCP 不保证事件边界
一个事件可能被切成两半送达
半截 JSON 喂给解析器，就是乱码和丢字


>>> 坑一 · 跨 chunk 缓冲 #B07
第一个坑，**跨 chunk 缓冲**
修法：每收到一块，先拼进缓冲区
再循环找双换行，凑齐完整事件才处理
切一半的留在缓冲区，等下一块到齐
所有流式客户端，骨子里都是这个结构


>>> 坑二 · 中文跨字节 #B08
第二个坑，中文用户专享
一个汉字是**三个字节**，可能正好被切在中间
半截字节直接解码，就是乱码
修法只有一行：decode 加上 **stream true**
让解码器自己留着不完整的字节


>>> 坑三 · 延迟的 done #B09
第三个坑，只有真机抓包才看得见
finish_reason 和 usage 不在同一块里
带 usage 的末块，choices 还是空数组
看到 finish_reason 就喊停，token 统计永远是零
正确做法：两个都先存着
**流结束时**再统一发 done 事件


>>> 假模型服务器 #B10
这三个坑，不能靠真机偶发去碰运气
我们写一个**假模型服务器**，按脚本回放字节流
想切在哪个字节就切在哪个字节，包括汉字中间
全部测试毫秒级，断网也能跑
能伪造协议，才说明你真的懂协议


>>> 客户端的形状 #B11
客户端做成 **async generator**
调用方 for await 消费，随时可以 break
你在 Claude Code 里按 ESC 停掉输出
背后靠的就是这套可中断的流式结构
第四课的中止功能，全建在这个设计上


>>> 见真章 #B12
一行命令，回答在终端里逐字蹦出来
思考过程用暗色显示，和正文分得清
你见过的那种灰字思考过程，就是这么来的
末尾一行 token 统计，是延迟 done 的兑现
它现在只会说话，不会做事
下一课，给它装手


>>> 拆开 pi 看一眼 #B13
同样这一层，打开 pi 的对应文件
一千五百七十七行，我们一百二十行
光思考字段它就认三个名字，还要防重复
因为它服务四十多家厂商，我们只打一个端点
多出来的一千四百行不是废话，是**兼容性税**
你的 agent 只打一个端点，就不必交这税
