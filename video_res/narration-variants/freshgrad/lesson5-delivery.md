>>> 第 5 课开场 #B01
最后一课不是讲课，是**交付**
前四课造的这一千来行的东西
到底能不能干真活
任务是真的，验收是自动化的
失败是公开的


>>> 任务定义 #B02
任务，在一个空目录里做登录应用
后端四个接口，sqlite 存用户
密码用 **scrypt** 加盐哈希，禁止明文
安全课上学过，库里绝不能存明文
会话用 httpOnly cookie，前端原生 JS
约束三条，零依赖、同一份 prompt、全程不干预


>>> 验收先行 #B03
关键设计，**验收先行**
冒烟测试十条，agent 进场前写好并锁定
就是软件工程课上的验收测试
最后一条最狠
直接搜数据库文件的原始字节
明文密码一个字节都不许出现
通过就是通过，没有商量


>>> 两道锁 #B04
agent 不许改考卷，上两道锁
第一道，路径约束让它够不到验收目录
但 bash 能用绝对路径绕过，我们诚实承认
第二道，**校验和**兜底
考卷改动一个字节，验收作废
声明式约束挡不住能执行任意命令的工具
这正是工业级产品要做沙箱的原因


>>> 裸跑开始 #B05
裸跑开始，全程录屏，不干预
跑在 Windows 加 Git Bash，模型在局域网
两轮用逐字相同的 prompt，校验和保证
课程原本预期它第一次会失败
但它失败的方式，谁都没猜到


>>> run1 实况 #B06
真实的第一次运行是这样的
它顺顺利利写完全部五个文件
然后想后台起个服务，自测一下
接着，**卡死了**
注意，这不是剧本
是这门课真实发生的事故


>>> 死锁解剖 #B07
用操作系统课的知识解剖它
工具等的不是进程退出
而是**全部标准输出关闭**
bash 被超时杀掉了
但后台服务还活着，手里握着管道
close 事件永远不来，这就是死锁
最后靠人手动杀掉那个进程，才恢复


>>> 失败记录表 #B08
事故记进**失败记录表**
现象、根因、对策，一一对应
预判清单里列了七项缺口
但没真实发生的，一个都不做
加固由**证据驱动**，不由想象驱动
这份表，是第五课最重要的产出


>>> 回炉 · 三层修复 #B09
一个事故，挖出三层修复
第一层，改成以进程退出为准返回
宽限一秒后主动销毁流，不再傻等
第二层，又发现外部杀不到后台任务
Git Bash 的后台任务，不在 Windows 进程树里
第三层，让 bash 退出前自己清场
一三层是通用的，第二层是 Windows 专属
每一步修复，都有实验证据


>>> run2 与验收 #B10
修完重跑，同一命令，同一份 prompt
从空目录，从零开始
这一次自测没有卡死
只用了 **7 步**、9 次工具调用
上次是 11 步、17 次
先验考卷，校验和一致
再跑冒烟测试，十条断言全绿


>>> 两次对比 #B11
两次对比，就是整门课的结论
有意思的是，登录应用两次都做出来了
差别在别的地方
第一次需要人工救一次
第二次一次都不需要
**把人从救援里解放出来**
这才是加固的意义


>>> 复盘收束 #B12
最后复盘三个问题
为什么能成
边界清晰、验收可执行、工具够用
为什么差点不成
每个简化决定，都会被真实任务逼出来
这门课的终点，不是造一个替代谁的 agent
而是获得**读懂它、并判断需不需要它**的能力
你怀疑过的那个黑盒，现在是你自己写的
