>>> 先看真实字节 #B06
先不写代码，用 curl 发一次流式请求
屏幕上滚过的东西叫 **SSE**
全称 Server-Sent Events，服务器推送事件
你就把它当成计网课上的应用层协议
每个事件以 data 冒号开头
事件之间用**两个换行**分隔
最后以 data 中括号 DONE 收尾


>>> 解剖一个事件 #B07
拆开一个事件看字段
content 是正文**增量**，不是完整回答
reasoning_content 是模型的思考过程
finish_reason 说明它为什么停下
所谓流式输出
就是把完整回答拆成碎片，逐个发给你


>>> 坑一 · 这题计网课上做过 #B08
知道协议长什么样，是不是觉得解析很简单
收到一块切一块就行
停，这题你在计网课上做过
**TCP 是字节流，不保证消息边界**
一个事件可能被切成两半送达
拿到半截 JSON 就解析
直接报错，或者吐乱码


>>> 缓冲区的修法 #B09
修法和课上讲的拆包一模一样
每收到一块，先拼进**缓冲区**
循环找双换行，凑齐完整事件才处理
切一半的留在缓冲区，等下一块到齐
说白了，消息边界要自己重建


>>> 坑二 · 汉字被切在中间 #B10
第二个坑，藏在字符编码里
UTF-8 里一个汉字是**三个字节**
网络切块可能正好切在字节中间
解码半截字节，终端就是一团乱码
修法只有一行
decode 加上 **stream true**
让解码器自己记住不完整的字节


>>> 坑三 · 真机才能发现的坑 #B11
第三个坑，不看真实字节流根本想不到
finish_reason 和 usage 不在同一块里
带 usage 的那块，choices 是空数组
看到 finish_reason 就发结束信号
token 用量就永远拿不到
正确做法，两个都先存着
**流结束时**再统一发 done


>>> 假模型服务器 #B12
这些坑，总不能靠真机偶发碰运气
我们写一个**假模型服务器**
它按脚本回放 SSE 字节流
想在哪切断就在哪切断，包括汉字中间
全部测试毫秒级，拔网线也能跑
记住这句话
能伪造协议，才说明你真的懂协议


>>> 客户端的形状 #B13
客户端做成 **async generator**，异步生成器
你就当它是个能 for await 的迭代器
想停就 break，天然支持提前退出
这个选择让第四课的中止便宜很多
测试也简单，收集成数组就能断言
