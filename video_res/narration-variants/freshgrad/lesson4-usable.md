>>> 第 4 课开场 #B01
第四课，回答一个很现实的问题
为什么 demo 里漂亮的 agent
一到真实任务就崩
因为真任务意味着聊得久、跑得长
会出错、明天还要接着干
这四件事**没有一件和智能有关**
但少一件，第五课就会死在半路


>>> REPL 与斜杠命令 #B02
先把一次一问，变成坐下来一直聊
readline 起个循环，加几个斜杠命令
查上下文用量、清空历史、保存会话
斜杠命令本地处理，**绝不发给模型**
我们刻意不做花哨的终端界面
你要始终看得见，发生了什么


>>> Ctrl+C 三层贯穿 #B03
本课的难点是**中止**
按了 Ctrl+C 它还在打字，你肯定遇到过
**AbortSignal** 就是 fetch 的那个取消信号
它必须贯穿三层，缺一层就漏
不传给 fetch，SSE 继续流，字还在蹦
不传给工具，bash 子进程继续跑
loop 不检查，下一步照常开始
三层都接上，Ctrl+C 才真正停得下来


>>> 中止的残局 #B04
中止后还有一盘残局
已经产生的部分输出，必须存进历史
没执行完的工具，补一条 aborted 结果
为什么这么较真
丢了它，下一轮上下文就有空洞
服务端直接 400
**完整性比干净更重要**


>>> 会话落盘 #B05
会话存成 JSONL，一行一条消息
消息一产生，立刻追加写
为什么不是退出时一次写完
因为崩溃、断电、Ctrl+C 都不该丢历史
这就是数据库课上的**日志先行**思路
追加写最多丢最后一行
读到坏行就跳过，不毁掉整个会话


>>> 上下文预算是内存管理 #B06
聊久了上下文会满，这会直接杀死会话
把上下文想成一块**固定大小的内存**
工具结果是大头，一次 read 几千 token
裁剪，就是操作系统课的**页面置换**
system 常驻，最近四轮优先保
从最老的开始丢
默认预算两万四，约为窗口的四成


>>> 系数要实测 #B07
估 token 不引依赖，但系数要**实测**
方法很土，发一次请求，读 usage 字段
实测中文零点五八 token 每字
代码三点七字符每 token
一刀切断以三，中文低估近两倍
那样裁剪形同虚设，反而保证会 400
十分钟的实测，胜过博客上抄的经验值


>>> 成组裁剪 #B08
裁剪有个必须正确的细节
assistant 和它的工具结果同生共死
要么都留，要么都丢
只丢一半，就产生孤儿 tool_call_id
你为了避免 400 做的裁剪
制造了**另一个 400**


>>> 重试的纪律 #B09
网络会抖，重试要克制
网络错误、五开头的、四二九
用带抖动的**指数退避**
和计网课上的冲突退避一个道理
其余四开头的，**绝不重试**
请求本身就是错的，重试只是重复失败
每次重试都打印出来，不许静默


>>> 首 token 分界线 #B10
流式请求的重试窗口只有一段
从发起到收到**第一个 token**
实现里收得更紧，响应头一到就锁死
这个窗口里失败，可以安全重来
已经吐了一半再重放，内容会重复
之后的失败，只能作为错误上报


>>> 见真章与 pi 对照 #B11
连续聊十几轮，不炸上下文
中途 Ctrl+C，只停本轮，还能继续
退出后再续聊，它还记得上文
对照 pi，它会把旧对话压缩成摘要
丢历史还是压历史，**没有免费的午餐**
到这里约一千二百行
它已经是一个每天能用的工具
