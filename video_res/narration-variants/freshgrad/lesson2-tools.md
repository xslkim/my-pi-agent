>>> 聊天机器人和 agent 的区别 #B01
第二课，先破一个迷信
聊天机器人和 agent 的区别是什么
答案短得让人失望
**一个 while 循环**
模型自己什么都不会执行
让它成为 agent 的，是我们写的循环
就像操作系统，硬件不会自己调度
靠的是那段不停转的调度循环


>>> 请求带上 tools #B02
第一步，请求体里加一个 **tools** 字段
每个工具就是名字、描述、参数 Schema
Schema 你就理解成函数签名
模型看到的，只有这张说明书
描述里要写清楚，别心算，请用计算器
不写这句，它经常绕过工具直接口算


>>> 响应变了 #B03
带上 tools 再问，响应就变了
正文是空的，多出来 **tool_calls**
注意，模型没有执行任何计算
它只是按格式说了一句
请帮我调这个工具，参数如下
这跟系统调用一个道理
应用只能提请求，干活的是内核
而这里，内核就是我们


>>> 坑一 · 参数是碎片 #B04
第一个坑，还是老朋友，粘包
工具参数是**一片一片**吐出来的
真实抓包里，数字二十一分成二和一两片
只有第一片带工具名，后面只有序号
必须按序号累加，流结束再解析
中途解析，拿到的是半个 JSON
它看起来像合法的中间状态，最容易骗过你


>>> 坑二 · 类型不是校验 #B05
第二个坑，写给学过 TypeScript 的你
**类型在运行时根本不存在**
Node 只是把类型注解删掉，什么都不检查
而模型一定会传错
字符串当数字、缺字段、调不存在的工具
所以要自己写一个六十行的校验器
数字宽容转换，报错精确到字段名


>>> 自愈机制 #B06
关键设计，校验失败**不抛异常**
把错误文本当工具结果，回给模型
模型读到缺参数，会自己补上重试
这是 agent 最重要的**自愈机制**
它看起来有智能，一部分就靠这个
亲眼看一次它自我纠错，比什么解释都管用


>>> agent loop #B07
现在写心脏，**agent loop**
调模型，收到 tool_calls 就执行
结果塞回消息列表，再调模型
直到模型不再要工具，循环结束
剥掉包装，所谓 agent 就是这个 while


>>> 消息顺序铁律 #B08
loop 里有一条铁律
带 tool_calls 的 assistant 消息
必须紧跟它的全部工具结果
少一条，下一轮请求直接 **400**
报错信息完全看不出根因
像数据库事务，要么整组提交，要么都别提交


>>> maxSteps 防死循环 #B09
真实模型会陷入死循环，反复调同一个工具
所以 **maxSteps 是必需品**，不是洁癖
没有上限，六万四的上下文会被烧光
然后服务端 400，整个会话作废
在本地免费模型上，这一幕很便宜
在按 token 计费的云上，这一幕**很贵**


>>> 真机坑 · 线上格式 #B10
分享一个只有真机才踩得出的坑
回传 tool_calls 必须用**线上格式**
要多包一层 function 包装
直接发内部结构，服务端直接 500
假模型测不出这个问题
因为它验收的，是我们自己定义的形状


>>> 见真章 #B11
问它，用计算器算二十一乘二加八
它先调乘法拿到四十二
再把四十二喂给加法，得到五十
注意，第二次的参数来自第一次的结果
到这里，它是一个 **agent** 了
全部代码五百五十行左右


>>> pi 对照与小结 #B12
对照 pi，它的循环**七百九十六行**
多出来的是并行工具、插话队列、生命周期钩子
每一个都对应我们刻意跳过的边界
但对理解 agent 是什么
一百来行的循环就够了
