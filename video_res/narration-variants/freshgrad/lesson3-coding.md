>>> 第 3 课开场 #B01
第三课，让它改代码
读文件、写文件、改文件、跑命令
就这四个工具，二十分钟能写完裸实现
但这一课真正难的不是怎么读文件
那是 fs.readFile 一行的事
难的是**怎么不让它把事情搞砸**


>>> 裸实现与兴奋 #B02
裸实现跑起来，它真的能改文件了
你会有点兴奋，我当年也兴奋过
接下来这一课，专门打碎这份兴奋
没有约束的 bash 加上会幻觉的模型
等于把 rm -rf 的执行权
交给一个喝醉的实习生


>>> 故障一 · 路径逃逸 #B03
故障一，**路径逃逸**
让它读工作目录外面的文件
它读到了，工作目录形同虚设
修法是 resolveInside
先 resolve 成绝对路径
再用 path.relative 判断越界，抛错


>>> 前缀陷阱 #B04
顺带一道陷阱题
为什么不用字符串前缀判断
因为 work 和 work-evil，前缀一模一样
**字符串前缀不等于路径包含**
这就是做题和工程的区别
边界情况不是加分项，是考点


>>> 软链与诚实的边界 #B05
相对路径挡住了，软链接还挡不住
目录里一个指向外部的链接就能绕过
已存在的路径，用 realpath 再验一次
但检查到真正读写之间，仍有竞态窗口
这就是操作系统课上的 **TOCTOU**
堵死它需要的系统调用，Node 没有暴露
**诚实画出约束的边界**，比假装安全有价值


>>> 故障二 · 上下文爆炸 #B06
故障二，上下文爆炸
一个五 MB 的文件塞进请求，直接 400
整个会话作废
修法是截断，默认两百行二十 KB
按 token 占比算，约占上下文的百分之八
关键是截断后**必须告诉模型**
它以为自己看完全文，比报错更糟


>>> 故障三 · edit 改错地方 #B07
故障三，edit 改错地方
文件里三处相同代码，replace 只改第一个
而且**静默失败**，没有任何报错
修法是本课最重要的规则，**唯一匹配**
出现多次就拒绝执行，并列出全部行号


>>> 错误信息是写给模型的 #B08
注意报错里那句，补充更多上下文
它不是写给人的，是**写给模型的**
模型读到，会去读那几行，补上下文重试
好的错误信息，本身就是 agent 的一部分


>>> 故障四 · 命令挂起 #B09
故障四，命令挂起
一个等输入的命令，能让 agent 永远卡死
修法是超时，加**杀进程树**
注意是进程树，操作系统课的老朋友
只杀 bash，会留下孤儿进程占着端口
Windows 用 taskkill，POSIX 杀进程组


>>> Windows 专属坑 #B10
Windows 上还有一个专属大坑
系统里有三个 bash，System32 那个是 **WSL**
在它眼里 G 盘是斜杠 mnt 斜杠 g
agent 用它写文件，报错还看不出根因
排查这个能耗掉一下午
所以 shell 要显式探测，优先 Git Bash
启动时打印一次路径自证


>>> system prompt #B11
工具装好了，还要告诉模型怎么用
system prompt 只有五条，短、具体、可执行
核心原则一句话
**prompt 说的和代码做的必须一一对应**
只写不做等于没写
做了不说，模型反复撞墙浪费轮次


>>> 见真章与对照 #B12
让它改一个文件，再跑命令验证
它先读，再改，再验证，最后汇报改动
亲眼看它干活的这一刻，约九百行代码
对照 pi，它踩了四十个坑，我们踩了四个
四个已足够理解这类工具的设计原则
下一课，把它变得每天能用
