# freshgrad 版旁白 · 改写策略说明

- **面向谁**：软件开发专业应届生，学过 OS/计网/数据结构但零工程经验，没用过 agent 工具，对「模型自己改代码」持怀疑态度。全篇用学长带学弟的第二人称口吻，第一课开场直接回应「这怎么可能」的怀疑，并给出「每个零件你都在课上见过」的定心丸。
- **类比全部换成课堂知识**：SSE 解析 ↔ 计网的 TCP 字节流/粘包拆包；tool_calls ↔ 系统调用（应用提请求、内核干活）；上下文裁剪 ↔ 页面置换（上下文 = 固定大小内存）；消息成组 ↔ 数据库事务；JSONL 追加写 ↔ 日志先行（WAL）；指数退避 ↔ 计网冲突退避；L5 死锁 ↔ OS 课的管道与进程等待。每个类比只在第一次出现时铺一句，不展开成第二堂课。
- **术语深浅**：所有术语首次出现都当场用一句白话解释（SSE、Schema、async generator、TOCTOU、scrypt、校验和等），并用 `**` 高亮；高亮取舍偏向「新手陌生的词」，像 400、500 这类状态码默认他们计网课见过，只简单带过。
- **结构重新设计**：仍保持五层能力递进（说话→动手→改代码→好用→交付），共 5 集 61 块。与原版相比，每集开头加了一个「破迷信/定心丸」块（如 L2 的 while 循环配调度循环类比）；L1 把「跨 chunk 缓冲」独立成块，因为粘包修法对新手是第一次见，值得单独一拍；L4 把上下文管理直接命名为「内存管理」，对齐 OS 课的已有心智模型。
- **事实核对**：行数、坑的细节、run1/run2 数据（11 步/17 次 vs 7 步/9 次、人工救援 1 次 vs 0 次）、token 系数（中文 0.58/字、代码 3.7 字符/token）、预算默认 24000 等均对照 docs/lessons/、docs/runs/、src/context.ts 核实；特别修正了叙事口径——run1 实际在人工救援后通过了验收（10/10），所以「两次都做成了，差别在要不要人救」，与 docs/runs/run1.md、run2.md 一致。
