>>> demo 和日用的差距 #B01
为什么 demo 里漂亮的 agent
一接真活就崩
因为真活意味着四件事
聊得久、跑得长、会出错、明天还得接着干
没一件和智能有关
但少一件，它就只是个玩具


>>> REPL 和斜杠命令 #B02
先把一问一答，变成坐下来一直聊
斜杠命令本地处理，**绝不发给模型**
查用量、清历史、存会话，都是本地操作
注意，我们刻意不做花哨的终端界面
出了事你得看得见发生了什么
黑盒界面只会耽误排查


>>> Ctrl+C 为什么停不下来 #B03
这课最难的是**中止**
Ctrl+C 按下去，它还在打字，气不气
因为取消信号 **AbortSignal** 要贯穿三层
不传给 fetch，流还在跑
不传给工具，bash 子进程还在跑
循环里不检查，下一步照常开始
三层都接上，Ctrl+C 才真停得下来


>>> 中止后的残局 #B04
停下来还不算完，有一盘残局要收
已经输出的部分，必须存进历史
没执行完的工具，补一条 aborted 结果
为什么这么较真
因为缺了它，下一轮上下文就有空洞
服务端直接 400
记住：**完整性比干净更重要**


>>> 会话落盘 #B05
会话存 JSONL，一行一条消息，追加写
为什么不是退出时一次性写文件
因为断电和 Ctrl+C 都不该丢历史
追加写最多丢最后一行
读的时候跳过坏行
崩溃留的半行，毁不掉整个会话


>>> 上下文是怎么花光的 #B06
聊久了上下文会满，然后服务端 400
谁吃掉的？自己加统计才知道
结论先给你：**工具结果是大头**
read 一次大文件就是几千 token
我们按窗口四成划了条安全线
超了就地裁剪，别等服务端翻脸


>>> token 系数要实测 #B07
token 估算不引依赖，但系数要**实测**
办法很土：发一次请求，读 usage 字段
实测出来：中文零点五八 token 一个字
代码三点七个字符一个 token
网上抄的一刀切除以三，中文能差两倍
估算错了，你的裁剪就是白做
十分钟实测，胜过十篇博客


>>> 裁剪要成组 #B08
裁剪策略很朴素
system 永远留着，最近四轮优先保
从最老的开始丢
但关键是**成组**丢
assistant 和它的工具结果，同生共死
只丢一半，造出孤儿 tool_call_id
你为避免 400 做的裁剪，制造了另一个 400


>>> 重试的纪律 #B09
网络会抖，但重试要克制
网络错误、五开头、四二九，退避重试
其他四开头的，**绝不重试**
四百通常是你消息结构本身错了
重试只是把同一个错再发三遍
还掩盖真 bug
每次重试都打印出来，别静默


>>> 首 token 是条分界线 #B10
流式请求能安全重试的窗口只有一段
从发起到收到**第一个 token**
实现里收得更紧：响应头一到就不再重试
窗口里失败，重来没副作用
已经吐了一半再重放，内容就重复了
所以首 token 之后失败，只能报错上去


>>> 见真章，对照 pi #B11
连续聊十几轮，不炸上下文
中途 Ctrl+C，只停本轮，还能接着聊
退出后再续聊，它还记得上文
对照 pi：它会把旧对话压缩成摘要
丢历史还是压历史，都要付代价
这就是工具和产品的差距
下一课，拿它去交付真东西
