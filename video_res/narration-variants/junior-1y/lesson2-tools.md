>>> 聊天和干活的区别 #B01
聊天机器人和 agent 差在哪
答案短得让人想吐槽
就差一个 **while 循环**
模型自己一行代码都不会执行
它只会说：帮我调下这个工具，参数在这
真正干活的，是你写的那段循环


>>> 给模型一张说明书 #B02
第一步，请求体里加个 **tools** 字段
每个工具就三样：名字、描述、参数 Schema
相当于你给模型写了一份接口文档
它看着文档决定调不调、传什么参
描述里要写清楚什么时候该用
不写清楚，它就绕开你的工具自己口算


>>> 响应变了，但它没干活 #B03
带上 tools 再问，响应不一样了
正文是空的，多出来 **tool_calls**
finish_reason 也变成了 tool_calls
看清楚，它没做任何计算
它只是按格式说了句：麻烦帮我调这个
执行，永远是你的事


>>> 坑一 · 参数是碎片 #B04
第一个坑，工具参数是一片一片吐出来的
真实抓包里，数字 21 是分成 2 和 1 两片来的
只有第一片带工具名，后面全是碎渣
必须按 index 攒齐，最后再 parse
中途 parse 必炸
而且炸之前那个半截，看起来像正常数据


>>> 坑二 · 类型在运行时不存在 #B05
第二个坑，后端同学最熟的那种
TypeScript 类型写得再漂亮
运行时全被擦掉，什么都不检查
模型一定会传错：字符串当数字、缺字段
所以自己写一个六十行的入参校验器
跟你给 Controller 写参数校验一个道理


>>> 报错别抛异常 #B06
关键设计：校验失败**不抛异常**
把错误文本当成工具结果，回给模型
它读到 op 字段必填，会自己补上重试
就像你接口返回了明确的错误码
调用方看着错误码自己改请求
这就是 agent 看起来有智能的主要来源


>>> agent loop 本体 #B07
现在写心脏，**agent loop**
调模型，它要工具就执行
结果塞回消息列表，再问一次
直到它不再要工具，循环结束
剥掉所有包装，agent 就是这个 while
你在脚本里写过的批处理循环，就长这样


>>> 消息顺序铁律 #B08
loop 里有一条铁律，记死
带 tool_calls 的 assistant 消息
后面必须紧跟它全部的工具结果
少一条，下一次请求直接 **400**
报错信息还完全看不出根因
跟消息队列少了 ack 一样难查
这条第四课还会回来坑你


>>> maxSteps 是熔断 #B09
真实模型会犯轴，反复调同一个工具
所以 **maxSteps 必须有**，相当于熔断
没有上限，六万四的上下文一会就烧光
然后服务端 400，整个会话作废
本地免费模型上，这只是难看
按 token 计费的云 API 上，这是真金白银


>>> 真机坑 · 回传格式 #B10
分享一个只有真机才踩得出的坑
回传 tool_calls 必须用**线上格式**
带 type 冒号 function，参数再包一层
直接发你内部的结构，llama.cpp 直接 500
假模型测不出来
因为它验的是我们自己定义的形状


>>> 跑一个看看 #B11
问它：用计算器算 21 乘 2 再加 8
它先调乘法，拿到 42
再把 42 喂给加法，得到 50
注意，第二次的参数来自第一次的结果
它会自己串调用了
到这一步，它是个真 agent 了


>>> 对照 pi 和小结 #B12
pi 的 loop 七百九十六行，我们一百来行
多出来的是并行工具、插话队列、各种钩子
都是边界情况，不是玄学
一百行的循环，足够你看懂原理
以后 Copilot 卡住、agent 犯傻
你大概能猜到它死在哪一层
下一课，给它能改代码的真家伙
