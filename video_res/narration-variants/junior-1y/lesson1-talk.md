>>> 这事和你有什么关系 #B01
你天天用 Copilot，或者公司封装的大模型接口
但说真的，你点下发送之后，网线上跑了什么
这一课就干一件事：把调大模型扒到字节层
学完你能自己写脚本直连模型，不碰任何 SDK
写业务的人，第一手本事就是看清接口


>>> 一次调用就是一次联调 #B02
调大模型，本质是一个 HTTP POST
和你联调后端接口没有区别
唯一特别的是响应不一次给完
是分期付款，一个字一个字吐
这个协议叫 **SSE**，服务器推送事件


>>> 先抓包再写代码 #B03
老规矩，联调先抓包
curl 一发，屏幕上滚的就是真实字节
每条 data 冒号开头，是一个事件
事件之间空一行，就是两个换行
最后来一条 data 中括号 DONE，收工


>>> 事件里都有什么 #B04
拆开一条事件看字段
delta.content 是正文，一次只给一小段
reasoning_content 是它的思考过程
finish_reason 告诉你它为什么停了
记住，你拿到的永远是**增量**，不是完整答案


>>> 先写个错的版本 #B05
按直觉写：收到一块就切一块
联调接口时你也这么干过吧
然后它就炸了
因为 TCP 不管你什么事件边界
一个事件可能被切成两半送到


>>> 坑一 · 跨包缓冲 #B06
第一个坑，事件被切成两半
半截 JSON 拿去 parse，直接报错
修法和你处理粘包一模一样
先拼进缓冲区，凑够两个换行再切
凑不齐的留着，等下一块到齐


>>> 坑二 · 中文切在字节中间 #B07
第二个坑，写中文的必踩
一个汉字在 UTF-8 里是**三个字节**
网络一切，正好切在字节中间
解出来就是乱码，跟乱码日志一个样
修法只有一行：decode 加上 **stream: true**
让解码器自己攒着不完整的字节


>>> 坑三 · 延迟的 done #B08
第三个坑，不看真抓包永远想不到
finish_reason 和 token 用量**不在同一块**里
看到 finish_reason 就收尾，usage 永远拿不到
正确做法：两个都先存着
流彻底结束了，再统一发 done
这个坑后面统计用量时会回来咬你


>>> 假模型服务器 #B09
这三个坑，靠线上偶发去碰，得排到明年
所以我们自己写一个**假模型服务器**
按脚本回放字节流，想在哪切在哪切
连汉字中间都能切
测试毫秒级跑完，拔网线都行
能伪造协议，才说明你真懂了协议


>>> 客户端的形状 #B10
客户端做成 **async generator**
调用方 for await 一段一段消费
想停就 break，天然支持
后面做 Ctrl+C 中止，全靠这个设计省钱
测试也好写，收集成数组直接断言


>>> 跑起来看看 #B11
一行命令，字在终端里一个一个蹦出来
思考过程用暗色，和正文分得清
末尾打一行 token 统计
坑三修对了没有，这里直接兑现
记住，它现在只会说话，不会干活
下一课，给它装手


>>> 对照工业级实现 #B12
看一眼工业级实现 pi 的兼容层
一千五百七十七行，我们一百出头
多出来的不是废话
是它要伺候四十多家厂商
光思考字段就得认三种名字
你只调公司内网那一个端点，就不用交这份**兼容性税**
看懂这税交在哪，你就不迷信 SDK 了
