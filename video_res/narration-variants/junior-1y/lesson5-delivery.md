>>> 最后一课是提测 #B01
最后一课不讲课，直接**交付**
前四课攒的这一千多行，到底能不能干活
任务是真的，验收是自动的
翻车是公开的
而且我们预期它第一次就会翻
**失败清单**，才是这课的主要产出


>>> 任务 · 登录应用 #B02
任务：空目录里做一个登录应用
后端四个接口，sqlite 存用户
密码 scrypt 加盐哈希，**禁止明文**
会话用 httpOnly cookie，前端原生 JS
约束三条：零依赖、prompt 两轮逐字相同
全程不许人插手


>>> 验收先行 #B03
关键设计，**验收先行**
冒烟测试十条，agent 进场前就写好锁死
从注册到登出全覆盖
最狠的一条：直接搜数据库文件的原始字节
明文密码一个字节都不许有
跟提测前先定验收标准一个道理
通过就是通过，没商量


>>> 两道锁 #B04
agent 不许改考卷，上两道锁
第一道，路径约束让它够不到验收目录
但 bash 能用绝对路径绕过去，这我们承认
所以第二道，校验和兜底
考卷改一个字节，这轮验收作废
声明式约束挡不住能执行任意命令的工具
这正是商业 agent 要做沙箱的原因


>>> 裸跑，不干预 #B05
裸跑开始，全程录屏，不干预
跑在 Windows 加 Git Bash，模型在局域网
考卷和 prompt 都在仓库里，照着就能复现
两轮运行 prompt 逐字一致，校验和保证
别急着期待它成功
失败清单才是主要产出


>>> run1 真翻车了 #B06
真实的 run1 是这样的
五个文件它写得顺风顺水
然后它想后台起个服务自测
接着，**卡死了**
注意这不是剧本
是这门课真实发生的事故


>>> 死锁解剖 #B07
解剖这次死锁
工具等的不是进程退出
而是**全部 stdio 关闭**
bash 超时被杀了
但后台服务进程还活着，手里攥着管道
close 事件永远不来
最后只能人工把那个进程杀掉


>>> 失败记录表 #B08
事故记进**失败记录表**
现象、根因、对策，一一对应
预判清单列了七项缺口
但 run1 里没出现的，一个都不修
加固由**证据驱动**，不靠想象
跟你复盘线上故障一个道理
没发生的问题不瞎优化
这份表，是第五课最值钱的产出


>>> 三层修复 #B09
回炉修复，一个事故挖出三层
第一层，工具改成以进程退出为准
宽限一秒后主动断流，不傻等 close
第二层，又发现外部杀不到后台任务
Git Bash 的后台任务不在 Windows 进程树里
第三层，让 bash 退出前自己清场
一三层通用，第二层是 Windows 专属
每一步修复，都有实验证据


>>> run2 全绿 #B10
修完，run2
同一条命令，同一个 prompt，从空目录重跑
这次没卡死
而且只用了 **7 步**、9 次工具调用

>>> run1 对 run2 #B11
run1 和 run2 的对比，就是整门课的结论
有意思的是，登录应用两次都做出来了
差别在：run1 要人工救一次
run2 一次都不用
**把人从救火里解放出来**
这才是加固的意义


>>> 复盘 · 和你工作的关系 #B12
最后复盘，说点和你工作直接相关的
它为什么能成
任务边界清晰、验收可执行、工具够用
你带 agent 干活，这三条缺一条就等着翻车
pi 那些看着过度设计的机制
摘要压缩、沙箱、并行工具、可恢复中止
每一个都对应我们亲手踩过的坑
