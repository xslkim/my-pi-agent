>>> 故障一 · 路径逃逸 #B03
让它读工作目录外面的文件
一路点点点往外翻
它真读到了，工作目录形同虚设
就像你接口没做权限校验，被人翻了库
修法是 resolveInside
用 path.relative 判断有没有越界，越界就拒


>>> 前缀陷阱 #B04
顺带一道陷阱题
判断越界，为什么不用字符串前缀
因为 work 和 work-evil，前缀一模一样
**字符串前缀不等于路径包含**
必须先 resolve 成绝对路径
再用 relative 看结果是不是两点开头


>>> 软链和诚实的边界 #B05
相对路径挡住了，软链接还能绕
目录里放个指向外面的链接，检查全失效
修法：已存在的路径，用 realpath 再验一次
但检查和真正读写之间，还有个竞态窗口
彻底堵死要的系统调用，Node 没暴露
**诚实画出能力边界**，比假装安全有用


>>> 故障二 · 上下文爆炸 #B06
让它读一个几 MB 的 lock 文件
请求直接 400，整个会话报废
上下文就是它干活的工作台，就这么大
修法是截断：默认两百行、二十 KB
关键是截断了**必须告诉它**
不然它以为看完了全文，照着残缺信息瞎改


>>> 故障三 · edit 改错地方 #B07
文件里三处长得一样的代码
replace 只改第一个，还没任何报错
**静默改错**，比报错可怕十倍
像 UPDATE 语句 WHERE 条件没写准
修法是这课最重要的规矩：**唯一匹配**
出现多次就拒绝执行，把所有行号列出来


>>> 错误信息是写给模型的 #B08
注意报错里那句「补充更多上下文」
那不是写给人看的，是**写给模型的**
它读到会自己去读那几行，补上下文重试
好的错误信息就是 agent 的一部分
跟你把接口错误码写清楚一个道理


>>> 故障四 · 命令挂起 #B09
一个等待输入的命令，能把 agent 卡死
修法是超时，然后杀进程
注意，是杀**进程树**，不是杀进程
只杀 bash，子进程变孤儿还占着端口
你本地起过的僵尸 node 服务，就这玩意
Windows 用 taskkill，POSIX 杀整个进程组


>>> Windows 专属坑 #B10
Windows 上还有个能吃掉一下午的坑
系统里有三个 bash，System32 那个是 **WSL**
进了 WSL，G 盘变成 /mnt/g
写错地方不说，报错还看不出根因
所以 shell 要显式探测，优先 Git Bash
启动时打印一次路径，让它自证清白


>>> system prompt 别写废话 #B11
工具装好了，还得告诉模型怎么用
system prompt 只写五条，短、具体、能执行
核心原则一句话
**prompt 说的和代码做的必须一一对应**
只写不做等于没写，模型会幻觉、会绕
做了不说，它会反复撞墙浪费轮次
