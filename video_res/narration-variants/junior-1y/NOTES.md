# junior-1y 变体 · 改写说明

面向：工作一年、写业务 CRUD、用过 Copilot 但没深究原理的程序员。他关心的不是"agent 是什么"，而是"这和我每天联调接口、查日志、写脚本有什么关系，学完明天能用上什么"。

- **重新设计了叙事入口**：每课开场不再从概念切入，而是从"这事和你有什么关系"切入。第一课把 SSE 讲成"分期付款的 HTTP POST"，第二课把 tool calling 讲成"给模型写接口文档、它当甲方提需求"，把抽象的协议学习挂到他天天做的接口联调上。
- **类比全部换成业务开发场景**：跨 chunk 缓冲 = 粘包处理；参数校验器 = Controller 入参校验；maxSteps = 熔断（云上烧 token = 真金白银）；edit 唯一匹配 = UPDATE 没带准 WHERE；失败记录表 = 线上故障复盘（没发生的问题不瞎优化）。删掉了纯理论性的铺垫（如"祛魅""工程哲学"这类表述），保留结论但落到工作语言。
- **结构上的取舍**：原版 lesson1 有 7 块课程导览（路线图、零依赖、三个固定环节等），对这个受众是冗余——他不关心课程教学法，只关心内容有没有用。所以把导览压进 B01/B13 两块，把省下的篇幅给"学完能带走什么"。五课的能力递进骨架（说话→动手→改代码→好用→交付）保持不变，仍是 5 集。
- **语气**：工位旁边同事的口吻，短句、直接、允许吐槽（"答案短得让人想吐槽""气不气""得排到明年"）。每课结尾加一句"和你工作的关系"式收束，回答他"学完能用在哪"。
- **高亮词的取舍**：只高亮他工作需要记住的抓手（SSE、tool_calls、maxSteps、唯一匹配、AbortSignal、验收先行、证据驱动），不再高亮教学法词汇（验收先行作为工作方法保留）。协议字段名（delta.content 等）不高亮，因为那不是他要记的概念，是讲解对象。
- **技术事实全部对照 docs/lessons、docs/runs 核对**：1577 行兼容层、796 行 loop、六十行校验器、200 行/20KB 截断、0.58 token/字与 3.7 字符/token、四成安全线、run1 11 步/17 次与 run2 7 步/9 次、三道 bash（WSL 路径 /mnt/g）、三层修复细节等，均与仓库一致。
