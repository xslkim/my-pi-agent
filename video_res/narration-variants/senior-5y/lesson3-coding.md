>>> 四件套 #B01
Claude Code、Cursor、pi，剥开都是同一套
read、write、edit、bash
裸实现二十分钟写完，它真的能改文件
先别兴奋
真正难的是 **怎么不让它把事情搞砸**

>>> 故障 A · 路径逃逸 #B02
让它读工作目录外的文件，它读到了
工作目录形同虚设
修法：**resolveInside**，用 path.relative 判越界
越界抛错，错误里保留原始输入

>>> 前缀陷阱 #B03
这里的常见错误做法：字符串前缀判断
work 和 work-evil，前缀一模一样
**字符串前缀不等于路径包含**
正确顺序：先 resolve，再 relative，再看结果是否两点开头

>>> 软链与诚实的边界 #B04
relative 挡不住软链：一个指向外部的链接绕过全部检查
修法：已存在路径用 **realpath** 再验一次真实位置
但从检查到真正读写之间，仍有 **TOCTOU 竞态**窗口
堵死它需要 openat 这类系统调用，Node 没有暴露
工具层只负责挡模型犯的错
挡主动攻击者，是沙箱的活
画出这条边界，比假装安全有价值

>>> 故障 B · 上下文爆炸 #B05
一个五 MB 的文件塞进请求，直接 400，会话作废
修法：截断，默认两百行二十 KB
阈值是算出来的：按三点七字符每 token，约占窗口 **百分之八**
关键细节：截断后 **必须告诉模型**
静默截断比报错更糟——它会基于残缺信息做判断

>>> 故障 C · edit 静默改错 #B06
文件里三处相同代码，replace 只改第一个
改错了，而且 **没有任何报错**
修法是本集最重要的规则：**唯一匹配**
多处匹配直接拒绝执行，并列出全部行号

>>> 错误信息是写给模型的 #B07
报错里两个细节：行号，和那句「补充更多上下文」
它们不是写给人的，是 **写给模型的**
模型读到会自己去读那几行，补上下文重试
错误信息是 agent 行为系统的一部分
只写给人看的报错，在这里是残次品

>>> 故障 D · 命令挂起 #B08
一个等待输入的命令，能让 agent 永久卡死
修法：超时，加 **杀进程树**
注意是树，不是进程
只杀 bash 会留下孤儿进程占着端口
Windows 用 taskkill 斜杠 T，POSIX 杀进程组

>>> Windows 的真坑 #B09
本机 where bash 返回三个结果
System32 那个是 **WSL**：G 盘在它眼里是斜杠 mnt 斜杠 g
用它跑 agent，写错位置，报错还看不出根因
排查这个能耗掉一下午
所以 shell 要 **显式探测**，优先 Git Bash
启动时打印一次实际路径自证
执行环境必须显式，不能靠 PATH 碰运气

>>> prompt 与代码的对账 #B10
system prompt 只有五条：短、具体、可执行
核心原则：**prompt 说的和代码强制的，必须一一对应**
只写不做，等于没写
做了不说，模型反复撞墙烧轮次
写 agent prompt，先对账，再措辞

>>> pi 对照 #B11
pi 的 edit 连 diff 组件 **六百多行**
执行环境 nodejs.ts 近 **七百行**
里面是多编辑、CRLF 保持、BOM、完整的 shell 候选链
我们踩了四个坑，它踩了四十个
四个已足够建立这类工具的设计直觉

>>> 小结 #B12
本集没有新协议，全是边界
路径、上下文、编辑、进程，四类约束各管一类搞砸
九百行，一个能改代码的 agent
下一集，把它从能跑变成能用
