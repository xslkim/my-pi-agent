>>> 祛魅：agent 是什么 #B01
聊天机器人和 agent 的差值是多少
答案短得丢人：**一个 while 循环**
模型自己什么都不执行
它只输出一段格式化文本：我要调这个工具，参数如下
把它变成 agent 的那段循环，是我们写的

>>> tools 字段 #B02
请求体里加 **tools**：名字、描述、一份手写 JSON Schema
对模型来说，这就是接口文档
注意 description 里那句：不要心算，请用计算器
不写这句，模型经常绕过工具直接口算
description 不是注释，是 **行为控制面**

>>> 响应形状变了 #B03
带上 tools 再问，响应变形状
content 空了，多出来 **tool_calls**
finish_reason 也变成 tool_calls
模型没有执行任何计算
它只是按协议说了一句：请帮我调这个，参数如下

>>> 坑一 · 参数是碎片 #B04
真实抓包：数字 21 是分成 2 和 1 两片吐出来的
只有第一片带 id 和 name，后面只剩 index
必须 **按 index 累加**，流收完再 parse
中途 parse 必炸
而炸之前那个中间态，看起来完全合法
「偶尔能跑」的 bug 都长这样

>>> 坑二 · 类型在运行时蒸发 #B05
TS 类型是编译期注解，运行时 **不存在**
类型剥离就是把它删掉，什么都不检查
而模型一定会传错：字符串当数字、缺字段、调不存在的工具
所以手写六十行校验器
关键取舍：数字 **宽容转换**，那是模型最高频的错误
错误信息精确到字段名

>>> 错误不回堆栈，回模型 #B06
关键设计：校验失败 **不抛异常**
把错误文本当工具结果回给模型
它读到 field op is required，自己补参数重试
这叫 **自愈**，是 agent 显得有智能的主要来源
把异常丢出循环，是新手方案

>>> agent loop #B07
心脏就这几行
调模型，收到 tool_calls 就执行
结果作为 tool 消息塞回 messages，再调模型
直到模型不再要工具
去掉包装，所谓 agent 就是这个 while，**九十行**

>>> 消息顺序铁律 #B08
一条铁律，违反必 400
带 tool_calls 的 assistant 消息
后面必须紧跟 **全部** tool 结果
少一条，服务端直接 400，报错完全看不出根因
记住这条，第四集它还会回来咬人

>>> maxSteps 不是可选项 #B09
真实模型会陷进死循环，反复调同一个工具
**maxSteps 是必需品**，不是防御性洁癖
没有上限，六万四的上下文会被烧光
服务端 400，会话作废
本地免费模型上这一幕很便宜
按 token 计费的云上，这一幕 **很贵**

>>> 真机坑 · 线格式 #B10
回传 tool_calls 必须用 **线上格式**
带 type function，外面再包一层 function
直接发内部形状，llama.cpp 返回 500
假模型测不出这个问题
它验的是我们自己定义的形状——闭环自证，不算数

>>> pi 对照 #B11
pi 的 loop **七百九十六行**，我们九十行
差额是并行工具、插话队列、beforeToolCall 钩子、精细中止
每一项都对应我们刻意跳过的边界
它的复杂度不是炫技，是把边界情况一个个补上
但理解 agent 是什么，九十行够了

>>> 小结 #B12
本集核心：tool calling 是协议，不是魔法
两个坑都来自流式，两个设计都来自模型不可靠
错误回喂和 maxSteps，记好这两笔
