>>> demo 为什么崩 #B01
demo 里漂亮的 agent，一到真任务就崩
因为真任务要求四件事
聊得久、跑得长、会出错、要续上
**没有一件和智能有关**
少任何一件，第五集死在半路
这一集全是状态管理，不性感，但是分水岭

>>> REPL 的取舍 #B02
一问一答改成 REPL，斜杠命令本地处理，**绝不发给模型**
查用量、清历史、存会话
刻意不做 **TUI**
差分渲染和光标控制会盖住事件流
你要始终看得见发生了什么，这是工具，不是产品

>>> 中止 · 三层贯穿 #B03
本集最难的是 **中止**
**AbortSignal** 必须贯穿三层，缺一层就漏
不传给 fetch：SSE 继续流，字还在蹦
不传给工具：bash 子进程继续跑
loop 不检查：当前步停了，下一步照常开始
三层接上，Ctrl+C 才真的停得下来
另外 Ctrl+C 有两个语义：干活时停本轮，空闲时才退出
REPL 靠一个 generating 标志区分这两种时刻

>>> 中止的残局 #B04
中止不是停下来就完事
已产生的部分输出，必须进历史
没执行完的工具，补一条 aborted 结果
为什么这么较真
丢了它们，下一轮上下文出现孤儿 tool 调用，服务端 400
**状态完整性比干净更重要**

>>> 会话落盘 #B05
会话用 **JSONL**，一行一条消息，产生即追加
为什么不在退出时整体写
崩溃、断电、Ctrl+C 都不该丢历史
追加写最多丢最后一行
读取时跳过坏行——崩溃留下的半行，不该毁掉整个会话
代价也摆在明处：没有分支、没有压缩、没有索引

>>> 上下文账怎么算 #B06
聊久了上下文会满，先搞清楚谁吃掉的
结论：**工具结果是大头**，一次 read 就是几千 token
安全线划在两万四，约窗口四成，超了就地裁剪
真超六万五千五，服务端才 400——到那步会话已经作废
预算要在本地算，不能等服务端替你报错

>>> token 系数要实测 #B07
估算不引 tokenizer，零依赖，但系数必须 **实测**
方法很土：发一次请求，读 usage 字段，减掉模板开销
实测结果：中文零点五八 token 每字，代码三点七字符每 token
两个常见错误取值都别犯
一刀切断以三：中文低估近两倍，裁剪形同虚设
一律按一字一 token：高估太多，历史被白白丢掉
十分钟实测，胜过抄来的任何经验值

>>> 裁剪必须成组 #B08
裁剪策略很朴素：保 system、保 **最近四轮**、从最老的开始丢
但有一条必须做对：**成组**
assistant 和它的全部 tool 结果，同生共死
只丢一半，产生孤儿 tool_call_id
你为避免 400 做的裁剪，制造了 **另一个 400**

>>> 重试纪律 #B09
网络会抖，重试要克制
网络错误、五开头、四二九：带抖动的指数退避
其余四开头：**绝不重试**
四百通常是消息结构有错
重试只是把同一个错再发三遍，还会掩盖真 bug
每次重试打印一行，不许静默

>>> 重试窗口 #B10
流式请求能安全重试的窗口只有一段
从发起到收到 **第一个 token**
实现里收得更紧：**响应头**一到手就不再重试
窗口内失败，可以安全重来
吐了半个回答再重放，内容会重复
首 token 之后的失败，只能作为错误上报

>>> pi 对照 #B11
对照 pi
上下文管理：它用 **compaction**，LLM 把旧对话压成摘要
会话：它有分支、状态机、崩溃恢复
中止：它区分中止和挂起，可恢复
丢历史还是压历史，**没有免费的午餐**
这些机制服务的是被人依赖的产品，代价是复杂度

>>> 小结 #B12
本集没有新能力，全是状态管理
中止、落盘、预算、重试
一千二百行，一个敢每天用的工具
下一集，拿它去交付真东西
