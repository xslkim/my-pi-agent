# NOTES · senior-5y 改写策略

面向读者：五年经验的资深程序员。设计过系统、带过项目，对「魔法宣传」免疫。他要的是架构切分、关键取舍、坑的位置——不是入门导论。

- **保留五集结构，重排块结构**：五层能力递进（说话→动手→改代码→好用→交付）本身就是这门课的架构主线，对资深读者依然成立，所以集数不动。但块级结构大改：原第 1 集 19 块压到 14 块，砍掉了「你每天都在用的黑盒」「三个固定环节」「开始第一课」这类暖场和课程运营内容——这类读者不需要被说服，把课程规则压缩进一句「每集一个 git 标签」即可。

- **基础概念一句带过，时间让给取舍**：SSE 帧格式、tool_calls 是什么，各用一块讲完，不铺垫。省下的篇幅全部投到决策点上：为什么用 async generator 而不是回调（背压 + 提前 break + 为中止铺路）、为什么数字参数做宽容转换、为什么截断阈值按 token 占比算账、为什么放弃对齐 pi 的 ls/grep 工具（无证据不做）。

- **按真实记录修正了叙事**：原旁白第 5 集沿用「预期失败」的剧本腔，但 docs/runs/run1.md 的真实结果是十条验收一次全绿、只发生一次工具层死锁。新版如实讲：run1 过了验收但死了一次，「预判七个缺口六个没发生」——这比剧本更有说服力，也正好支撑「证据驱动加固」这条主线。

- **直白点名常见错误做法**：评审会语气，直接指出反模式——字符串前缀判路径包含、中途 parse 增量参数、把异常丢出 loop、静默重试、给想象中的 agent 加固。每条都对应仓库里的真实修法。

- **高亮词按受众重选**：删掉面向新手的「黑盒」「自愈机制」式情绪词，高亮集中在协议字段、机制名和数字上（**兼容性税**、**TOCTOU 竞态**、**AbortSignal**、**compaction**、**证据驱动**），都是资深读者会拿去检索或复述的术语。

- **关键数字全部对仓库实测复核**：loop.ts 90 行、llm.ts 149 行（l1 标签下 78 行）、src 总计 1106 行、pi 兼容层 1577 / loop 796 / edit 600+ / nodejs.ts 695，均与 git tag 和 docs/lessons 一致；run1/run2 的步数与调用数（11 步 17 次 → 7 步 9 次）以 docs/runs 为准。
