# 方案 2 · 受众画像先行法（受众驱动 · 写作主法）

> **一句话定位**：先写清楚「说给谁听」，再决定怎么讲。脚本的所有取舍都从一张受众画像推导，不凭作者感觉。
> **什么时候选它**：受众混杂或拿不准深浅；同一内容要出多类受众的版本；过往视频被反馈「听不懂」或「太啰嗦」。
> **用法**：本方案是三个**写作主法**之一（01 结构 / 02 受众 / 04 块设计），每次课程按症状三选一；两道**通用工序**（03 事实基线 · 05 音画验收）不在选择之列，每次必过。本文件自包含；编号即流水线位置，非优先级。脚本格式规范以 AutoVideo 的 `docs/AUTHORING.md`（本机 `/home/xsl/AutoVideo/docs/AUTHORING.md`）为准；文中相对路径均相对 my-pi-agent 仓库根。

---

## ① 确定目标

让脚本的所有可变决策——开场钩子、类比选择、术语深浅、高亮词、语气、跟练支持——都有一致、可解释的出处：**受众画像**。换一个画像，能系统性地产出另一个版本，而不是随机改几句。

## ② 怎样才能达成

- **画像不是人口统计学，是认知状态**。核心四件事：他已经知道什么（知识基线）、天天接触什么（日常场景）、脑子里已有的心智模型、对主题的怀疑或痛点；画像卡再加两栏：从知识基线与心智模型整理出的类比库、他不想听的内容（避雷清单），即 ③.1 的六栏。写不出核心四条的画像没有决策价值。知识基线栏写具体技术清单（「学过计网、写过 HTTP 接口」），不写「有计算机基础」这类笼统话——笼统基线会把 SSE、异步迭代器这类概念误判成「他本来就会」，前置断裂大都这么来。
- **本系列默认受众（程序员 / CS 学生）的五条共性先当公理**：能读代码、有工程概念、讨厌废话、会暂停跟练、对「魔法宣传」免疫。画像卡只记他与基线的差异；贩卖神奇、零基础铺垫、把画面已有内容再念一遍，默认进避雷清单，不必逐次论证。
- **钩子**：从他的日常场景里选他亲眼见过的现象（agent 重度用户 → 「ESC 有时停不下来」；应届生 → 「模型自己改代码，这怎么可能」）。
- **类比**：从他的知识基线里选，每个核心概念配一个他领域的类比，首次出现铺一句即收，不展开成第二堂课（应届生：SSE 粘包 ↔ 计网 TCP 字节流；业务程序员：参数校验 ↔ Controller 入参校验）。
- **术语深浅**：概念按来源三分——他本来就会：直接用；本系列前集讲过：给一句回忆钩（「上集的跨 chunk 缓冲」）带过，不重讲；本集新教：当场一句白话解释。观众可能从中间一集进来、或隔了几周才续看，不假设他记得前集细节（每集开场一句本集定位的要求见通用底线 8）。
- **高亮词**：只给他需要记住、会拿去检索或复述的词；情绪词、教学法词汇不高亮。
- **语气**：画像决定距离感（近如学长带学弟，远如评审会），全系列统一。
- **跟练与自验**：他会暂停跟练——演示命令整段可复制运行，环境与版本在首次相关处一句交代；关键结果给出可自验的预期（「你这边应该看到 7 步 9 次工具调用」），命令与数字以事实表（通用工序 03）为准。

## ③ 具体步骤

1. **写画像卡**（≤6 行，一栏一行）：知识基线 / 日常场景 / 已有心智模型 / 对主题的怀疑或痛点 / 他能听懂的类比库 / 他不想听的内容。信息来源：任务给出的受众描述优先；没有就从已有脚本与 `video_res/narration-variants/` 五版画像推断，或先借其中最接近的一版改两栏；推断得出的栏目标注「假设」，随决策表一起送确认，不留空。
2. **推导决策表**：开场钩子来源、类比池（本集每个核心概念各配一个类比）、术语解释深度（概念三分：本来就会直接用 / 前集讲过给回忆钩 / 本集新教当场一句白话）、高亮词清单、语气、跟练与自验方式（命令可复制、环境前置一句、关键结果给可自验预期）。决策表必须先于写稿存在。
3. **存档**：画像卡与决策表存为脚本同目录的 `NOTES.md`（写法参照 `video_res/narration-variants/*/NOTES.md`），后续改稿、出变体都以此为基准。
4. **按决策表写正稿**：正稿即 AutoVideo 三件套 `meta.md` / `visuals.md` / `narration.md`（格式以 AutoVideo `docs/AUTHORING.md` 为准）；概念首次出现给一句白话解释、演示给可复制的命令与可自验的预期结果，均按决策表执行。写完后过两道通用工序（03 事实基线、05 音画验收），并按文末「通用底线」过一遍。
5. **审稿用「预设问题清单」，不做自由角色扮演**：让 LLM 自由扮演读者有回音室风险——扮演者的先验与作者同源，「他没见过的词」容易被漏报。改为：从画像卡的「怀疑与痛点」栏生成一份刁钻问题清单，逐块问「这段回答了这条怀疑吗」；有真人观众时，用一次真人抽评校准决策表，之后模型审稿只做增量（只复核校准后改动过的块）。
6. **多受众变体（可选）**：技术主干与事实数字不变，换画像卡 + 决策表出新版。变体以一份已核实的事实表（通用工序 03 的产物）为前提；若当次课程未建过，先补一张最小事实表（只列本集出现的数字、版本、行数、文件名及各自核实出处）再出变体，不要凭记忆沿用数字。

## 通用底线（任何方案都必须守）

> 本节在五份文档中逐字一致，修改须五处同步（可用 `video_res/guidelines/check-baseline.sh` 校验）。

1. 结构合规：visuals.md 与 narration.md 块 ID 一一对应，指令只写 visuals.md；`slug` 全小写显式声明。
2. 旁白每行一句，中文 ≤50 字（推荐 15–25 字）；`**` 高亮每行 ≤1 处，只给要记的术语和数字。
3. 中文旁白不夹英文短语（TTS 发音不可控），无法避免的外文词交给发音词典；含数字的事实冻结「上屏形式」（卡片写法）与「上口形式」（旁白念法）。
4. 脚本中每个数字/行数/版本/文件名/命令都对代码库核实过（命令以逐字执行为核查方式，代码状态相关的事实注明参照快照），同一事实全系列口径唯一；核实失败的标「未核实」，未核实事实不进脚本。
5. 视觉模式优先级：静态能表达 → `html`；必须跟随旁白的动效 → `animation`（声明 `props.lineTimings` 驱动，跟随旁白处禁绝对时间戳，入场编排的 `[Xs]` 节拍允许）；真实运行画面 → `video(./path)` 实录。
6. 音画时长三档（块时长按「字数 ÷ 校准字/秒 + 行数 × 0.2s」估算，系数未校准时先用约 4.5 字/秒兜底）：素材 ≥ 块时长 = 安全（超时自动截断）；块时长 ÷ 1.5 ≤ 素材 < 块时长 = 可接受（循环 ≤1.5 次）；素材 < 块时长 ÷ 1.5 = 必改（重录、放慢回放、扩大区间或 `@duration` 对齐）；时长超预算时先砍块、不砍字（整块删最弱块，不逐句压字）。
7. 画面背景填满全屏，内容避让底部字幕安全区（1080p 为 120px，其他分辨率按 高 × 120/1080 换算）。
8. 每集开头一句本集定位（做什么、从哪个产物或 git tag 接着做），结尾留下一集钩子（系列末集以全系列收束或延伸阅读指引替代）；敏感信息（token、内网地址、用户名）一律占位符。
9. 写作中间产物（契约、画像卡、决策表、时长预算表、NOTES.md 等）存脚本同目录的 Markdown 文件，不进 project.json、不参与编译；事实表例外：全系列共用一张，存系列公共位置（如 `video_res/facts.md`）。

## 依据

- 内部：`video_res/narration-variants/` 五个受众版本的 `NOTES.md`——本方法的实战验证与格式样板；其中 `senior-5y/NOTES.md`（「对魔法宣传免疫」、砍掉暖场与课程运营块）与 `junior-1y/NOTES.md`（七块课程导览压进两块）是程序员受众避雷清单的实证。
- [University of Reading 教学视频研究简报](https://research.reading.ac.uk/design-research-for-testing-diagnostics/wp-content/uploads/sites/178/2021/02/Research-Briefing_Instructional-videos_february-2021.pdf)：口语化与对话式语言的建议，支持「语气由画像推导」这条决策。
