# 方案 1 · 三层目标契约法（结构驱动 · 写作主法）

> **一句话定位**：先签合同，再动笔。系列、单集、块三层各立一句可验收的目标，自顶向下分解，反向追问对齐。
> **什么时候选它**：一套全新系列从零起步；或出现过结构松散、内容膨胀、块与主题脱节的问题。
> **用法**：本方案是三个**写作主法**之一（01 结构 / 02 受众 / 04 块设计），每次课程按症状三选一；两道**通用工序**（03 事实基线 · 05 音画验收）每次必过。本文件自包含；编号即流水线位置，非优先级。脚本格式规范以 AutoVideo 的 `docs/AUTHORING.md`（本机 `/home/xsl/AutoVideo/docs/AUTHORING.md`）为准；文中相对路径均相对 my-pi-agent 仓库根。

---

## ① 确定目标

系列、单集、块三层各有一句**可验收的目标**，且严格对齐：块目标的合集 = 单集目标，单集目标的合集 = 系列目标。任何一层说不出「看完能干什么」，就还没资格动笔。

| 层 | 目标要回答的问题 | 示例（本仓库五课系列） |
|---|---|---|
| 系列 | 观众看完全部，**能做出/说出什么**？ | 能从零写出一个 1100 行的 coding agent，并讲清每一层为什么 |
| 单集 | 这一集交付哪一级**能力台阶**（从哪出发、到哪结束）？ | 第 1 课：让模型说话——手写 SSE 客户端，终端逐字看到回答 |
| 块 | 这一块观众**带走哪一句话**？ | 「TCP 不保证事件边界，天真解析器必丢字」 |

## ② 怎样才能达成

- **目标写成可观察行为**：禁止「介绍」「讲解」「了解」「掌握」「精通」这类无法验收的动词；目标动词用工程动词：手写、跑通、定位、说出为什么。
- **先定终点，再拆台阶**：系列目标 = 终点能力；单集目标 = 能力递进的一级台阶；块目标 = 一个且仅一个要点。顺序依赖必须成立：第 N 集用到的概念，必须在前 N-1 集讲过，或属于受众既有知识；前集概念在本集首次出现时给一句回指（如「上一集的手写解析器」），不裸用、不重讲。
- **目标里写明不做什么**（范围护栏）：「不 import pi、零依赖」（`docs/teaching-agent-plan.md` §1）与「累计 ≤1400 行」（同文件 §4）是系列级样板。

## ③ 具体步骤

1. **写系列目标契约**（≤5 行）：受众一句话（含默认他会什么，如「写过 TypeScript、日常用命令行」）/ 看完获得的能力一句话 / 明确不讲的范围 / 跟练前置（环境基线一句话，如「Node ≥ 23.6、零依赖」）/ 每集交付物（能跑的产物 + git tag + 一条可执行的验证方式如 `node --test`；tag 是观众暂停跟练时对齐环境的锚点）。
2. **画单集递进图**：每集一句话目标 + 一行「为什么排在上一集之后」+ 入口状态（从哪个 tag 出发、本集假设的既有知识）。检查概念依赖链是否成立；不成立就调集序、补一集前置，或把该概念显式声明为「受众既有知识」并不再展开。入口状态供中途入场的观众（常从搜索直达中间一集）判断要不要回补前置、checkout 哪个 tag 对齐环境。
3. **列块清单**：每块一行「本块要点」，并标注它支撑哪条单集目标。**块数不是硬约束，时长才是**（本课程第 1 课 19 块仍被评审认可）：每集 10–20 块、单块 15–40 秒是参考区间，集总长 4.5–7 分钟是硬约束。时长估算公式与 4.5 字/秒兜底系数见文末「通用底线」第 6 条（系数校准见通用工序 05）；契约阶段还没有旁白全文，按行数预算粗估（如每块 4–8 行 × 约 20 字/行）。估算落出区间就调结构：总长超上限砍块或拆集、不足下限并块或补块；单块超 40 秒拆、不足 15 秒并。
4. **对齐检查**（反向追问）：任意挑一块，能说出它支撑哪条单集目标；任意挑一条单集目标，能指出由哪几块支撑；对不上的块删掉。再逐集问「删掉它，系列目标是否仍成立」——成立说明它是脂肪，砍。
5. **契约存档**：三层目标写进独立的 `plan.md`，全系列只存一份（系列公共位置或首集的项目目录：本仓库即 `video_res/lesson*/`，AutoVideo 侧即 `project/<项目名>/`），各集引用同一份；**不要**写进 meta.md 注释（meta.md 是编译解析对象，AUTHORING 只定义了视觉描述里的 `<!-- -->` 注释，meta.md 中注释容忍度未定义）。同一份契约里冻结**系列视觉语义表**：叙事各方的卡片颜色（如「我们」一方 accent 蓝）、图标、卡片语言（卡片文案的中/英文口径）、错误态色（如 `#f85149`），系列级一次冻结、逐集引用。
6. **按契约写正稿**：每块围绕它的一句话要点展开；写完后过两道通用工序（03 事实基线、05 音画验收）和文末「通用底线」。

## 给 LLM 的提示词模板

> 空位（`___` 与【】）由发令方填写后使用；留空时执行方先自行盘点相关路径、列出待确认清单，再开始。本仓库语境下：路径清单可填已有各集脚本 `video_res/lesson*/`、参考文档 `docs/teaching-agent-plan.md`、事实表（通用工序 03 的产出，若无则先按 03 补一张）；受众如「有计算机基础的程序员和 CS 学生」。

```
动笔前先读：【路径清单：已有各集脚本 / 参考文档 / 事实表（若有）：___】。
我们要做一套《___》系列技术教程，受众是 ___。
请先不要写脚本。先输出三层目标契约：
1. 系列目标：观众看完全部能 ___（可观察行为）；明确不讲 ___；
   跟练前置（环境基线）___；每集交付物 = 能跑的产物 + git tag + 一条可执行的验证方式；
2. 单集递进：分 ___ 集，每集一句话目标 + 一行为何排在上一集之后
   + 入口状态（从哪个 tag 出发、本集假设的既有知识）；
3. 每集块清单：每块一句话要点 + 支撑的单集目标；
   每集 10–20 块、单块 15–40 秒为参考，集总长 4.5–7 分钟为硬约束；
4. 系列视觉语义表：叙事各方的卡片颜色、图标、卡片语言、错误态色（系列级冻结）。
等我确认契约后，先把契约存入项目目录 plan.md，再逐集展开成 meta.md / visuals.md / narration.md。
写正稿时：每块只服务它自己的一句话要点，与契约无关的内容一律不写。
```

## 通用底线（任何方案都必须守）

> 本节在五份文档中逐字一致，修改须五处同步（可用 `video_res/guidelines/check-baseline.sh` 校验）。

1. 结构合规：visuals.md 与 narration.md 块 ID 一一对应，指令只写 visuals.md；`slug` 全小写显式声明。
2. 旁白每行一句，中文 ≤50 字（推荐 15–25 字）；`**` 高亮每行 ≤1 处，只给要记的术语和数字。
3. 中文旁白不夹英文短语（TTS 发音不可控），无法避免的外文词交给发音词典；含数字的事实冻结「上屏形式」（卡片写法）与「上口形式」（旁白念法）。
4. 脚本中每个数字/行数/版本/文件名/命令都对代码库核实过（命令以逐字执行为核查方式，代码状态相关的事实注明参照快照），同一事实全系列口径唯一；核实失败的标「未核实」，未核实事实不进脚本。
5. 视觉模式优先级：静态能表达 → `html`；必须跟随旁白的动效 → `animation`（声明 `props.lineTimings` 驱动，跟随旁白处禁绝对时间戳，入场编排的 `[Xs]` 节拍允许）；真实运行画面 → `video(./path)` 实录。
6. 音画时长三档（块时长按「字数 ÷ 校准字/秒 + 行数 × 0.2s」估算，系数未校准时先用约 4.5 字/秒兜底）：素材 ≥ 块时长 = 安全（超时自动截断）；块时长 ÷ 1.5 ≤ 素材 < 块时长 = 可接受（循环 ≤1.5 次）；素材 < 块时长 ÷ 1.5 = 必改（重录、放慢回放、扩大区间或 `@duration` 对齐）；时长超预算时先砍块、不砍字（整块删最弱块，不逐句压字）。
7. 画面背景填满全屏，内容避让底部字幕安全区（1080p 为 120px，其他分辨率按 高 × 120/1080 换算）。
8. 每集开头一句本集定位（做什么、从哪个产物或 git tag 接着做），结尾留下一集钩子（系列末集以全系列收束或延伸阅读指引替代）；敏感信息（token、内网地址、用户名）一律占位符。
9. 写作中间产物（契约、画像卡、决策表、时长预算表、NOTES.md 等）存脚本同目录的 Markdown 文件，不进 project.json、不参与编译；事实表例外：全系列共用一张，存系列公共位置（如 `video_res/facts.md`）。
