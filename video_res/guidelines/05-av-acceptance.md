# 方案 5 · 音画预算与验收回路法（落地驱动 · 通用工序）

> **一句话定位**：把「验收先行」用到脚本生产本身。脚本交给构建之前，先算账、先选模式、先过验收清单——它必须是可构建、节奏对、口径稳的成品。
> **什么时候用它**：**每次课程必过**——它是交构建前的质量门，防构建翻车（音画穿帮等）。
> **用法**：本方案是**通用工序**，不参与写作主法的「三选一」（主法在 01/02/04 中选）。本文件自包含；编号即流水线位置，非优先级。脚本格式规范以 AutoVideo 的 `docs/AUTHORING.md`（本机 `/home/xsl/AutoVideo/docs/AUTHORING.md`）为准；文中相对路径均相对 my-pi-agent 仓库根。

---

## ① 确定目标

脚本在交付构建**之前**通过一份逐项可判对错的验收清单：视觉模式全部选对、音画时长全部匹配、系列口径一致、演示可按原顺序复现。构建后只剩抽查，不再返工。

## ② 怎样才能达成

- **时长先算账**：按「字数 ÷ 校准字/秒 + 行数 × 0.2s」估算块时长（字数按去掉 `**` 高亮符的旁白纯文本计，行数按非空旁白行计，0.2s 即 AUTHORING §4.1 的行间 200ms 静音），先有时长预算，再决定视觉。时长系数必须按音色实测校准（见步骤 1）——~4.5 字/秒只是 B00 音色的量级参考，换音色、换语速配置后未必成立。
- **音画时长三档规则**：
  - 素材 ≥ 块时长：**安全**，超时自动截断（AUTHORING §3.2）；
  - 块时长 ÷ 1.5 ≤ 素材 < 块时长：**可接受**（循环 ≤1.5 次；追求完美则补录）；
  - 素材 < 块时长 ÷ 1.5：**必改**（重录、放慢回放、扩大录制区间或用 `@duration` 对齐；18s 旁白配 3.4s 素材、循环 5.4 次的 pi-scroll 穿帮事故就在这一档）。
- **视觉模式按 AUTHORING §3.0 优先级**：
  - 静态能表达（精确文字/代码/数据）→ `html`；
  - 必须跟随旁白推进的动效（逐条高亮、流程推进）→ `animation`，且描述中声明用 `props.lineTimings` 驱动、禁绝对时间戳（TTS 时长每次会变，硬编码时间戳会静默错位）；
  - 真实运行画面 → `video(./path)` 实录，并在 `<!-- -->` 注释里记录录制命令。
  - 留白多的画面（单一标题、简单对比）不要给 `animation`——coverage 质量门会反复重试甚至失败。
- **口径一致性也是验收项**：视频实际时长与旁白里的「课时」说法不能矛盾（REVIEW D1：标注仅 4.5–7 分钟的视频里念「接下来的四十分钟」）。

## ③ 具体步骤

1. **校准系数，做时长预算表**：音色以 meta.md 的 `voiceRef` 为准。每个音色首次使用时，先用管线的 tts 阶段合成 3–5 行代表性样本（BUILD.md：`autovideo tts --block` 可按块单独合成），`ffprobe` 量出样本音频总时长，按「系数 = 样本总字数 ÷（音频总时长 − 样本行数 × 0.2s）」回填——与估算公式同口径，剔除行间静音。再逐块算估算时长（字数 ÷ 系数 + 行数 × 0.2s），累加成集时长（硬约束 4.5–7 分钟）。预算表注明所用系数与校准日期，存进项目目录随脚本走——它就是验收模板路径清单里的「时长系数校准记录」。超预算先砍块、不砍字：整块删掉与单集目标关联最弱的块，而不是逐句压缩旁白字数（逐句压字伤节奏、易致口径漂移）。
2. **逐块选视觉模式**：按上面优先级决策；video 块的素材时长用 `ffprobe` 实测（或素材目录自带的时长记录），按三档规则核对并记入预算表；落在必改档又没条件重录时，用其余三招兜底。
3. **过预构建验收清单**：
   - 结构：两文件块 ID 一一对应；指令只写在 visuals.md；`slug` 全小写显式声明
   - 字幕：全量扫描无超 50 字的行（计数规则见 AUTHORING §4.4：中文 1 字 1 计数、标点也算）；中文旁白无英文短语
   - 可读性：上屏文字与代码的字号不低于 AUTHORING §3.1 最低字号表（1080p：正文 ≥28px、代码块 ≥24px）——观众会暂停读屏照敲，字小即硬伤
   - 事实：所有数字有出处且全系列口径唯一（含数字的上屏/上口形式已冻结）
   - 敏感信息：全量扫描无明文 token、无内网地址、无真实用户名（REVIEW E 节第 4/5 条的教训）
   - 音画：animation 块声明 lineTimings、跟随旁白的推进不用绝对时间戳（入场编排的 `[Xs]` 节拍允许）；video 素材全部落在三档规则的前两档；画面背景填满全屏、避让底部字幕区（1080p 为 120px，其他分辨率按 高×120/1080 换算，AUTHORING §3.1）
   - 叙事：每集开头独立可入——开场块交代本集做什么、从哪个产物或 git tag 接着做，不假设观众记得上集细节（观众可能从中间一集进场）；每集结尾有下一集钩子（系列末集无下一集时，以全系列收束或延伸阅读指引替代，不判不通过）；系列口径（术语、称呼、进度说法）一致
   - 视觉语义：本集画面符合系列视觉语义表（各方的颜色/图标/卡片语言/错误态色一致）；语义表缺失时，先从已交付各集归纳一张落盘再对照；系列首集无表可归纳时，本集先定义一张（存系列公共位置或本集目录），后续集对照
   - 跟练：本集演示的命令与代码按展示顺序在真实环境完整跑通过一遍（工序 03 核单个事实，这里核整条演示链路）；演示起点状态（上一集产物或 git tag）已在脚本或 NOTES.md 标明，观众能从同一起点复现；纯概念讲解、无演示可跑的集跳过本项
   - 环境：构建前 `autovideo doctor` 通过（TTS / Agent 服务在线）
4. **构建后抽查成片**：构建由构建 agent 按 BUILD.md 执行；拿到 MP4 后随机抽 3 块，`ffmpeg` 抽帧看字幕换行与素材循环、对照预算表的块时长核对音画对位。有问题回到对应工序修，不留到下一集。
5. **清单回写**：本次发现的每个新问题，作为项目专属条目追加进步骤 3 的清单（维护本系列自己的清单副本，不改本文档），下次验收直接可用。

## 通用底线（任何方案都必须守）

> 本节在五份文档中逐字一致，修改须五处同步（可用 `video_res/guidelines/check-baseline.sh` 校验）。

1. 结构合规：visuals.md 与 narration.md 块 ID 一一对应，指令只写 visuals.md；`slug` 全小写显式声明。
2. 旁白每行一句，中文 ≤50 字（推荐 15–25 字）；`**` 高亮每行 ≤1 处，只给要记的术语和数字。
3. 中文旁白不夹英文短语（TTS 发音不可控），无法避免的外文词交给发音词典；含数字的事实冻结「上屏形式」（卡片写法）与「上口形式」（旁白念法）。
4. 脚本中每个数字/行数/版本/文件名/命令都对代码库核实过（命令以逐字执行为核查方式，代码状态相关的事实注明参照快照），同一事实全系列口径唯一；核实失败的标「未核实」，未核实事实不进脚本。
5. 视觉模式优先级：静态能表达 → `html`；必须跟随旁白的动效 → `animation`（声明 `props.lineTimings` 驱动，跟随旁白处禁绝对时间戳，入场编排的 `[Xs]` 节拍允许）；真实运行画面 → `video(./path)` 实录。
6. 音画时长三档（块时长按「字数 ÷ 校准字/秒 + 行数 × 0.2s」估算，系数未校准时先用约 4.5 字/秒兜底）：素材 ≥ 块时长 = 安全（超时自动截断）；块时长 ÷ 1.5 ≤ 素材 < 块时长 = 可接受（循环 ≤1.5 次）；素材 < 块时长 ÷ 1.5 = 必改（重录、放慢回放、扩大区间或 `@duration` 对齐）；时长超预算时先砍块、不砍字（整块删最弱块，不逐句压字）。
7. 画面背景填满全屏，内容避让底部字幕安全区（1080p 为 120px，其他分辨率按 高 × 120/1080 换算）。
8. 每集开头一句本集定位（做什么、从哪个产物或 git tag 接着做），结尾留下一集钩子（系列末集以全系列收束或延伸阅读指引替代）；敏感信息（token、内网地址、用户名）一律占位符。
9. 写作中间产物（契约、画像卡、决策表、时长预算表、NOTES.md 等）存脚本同目录的 Markdown 文件，不进 project.json、不参与编译；事实表例外：全系列共用一张，存系列公共位置（如 `video_res/facts.md`）。
